# Reasoning：分析本轮、审视整体并选择下一步

默认依次认真分析本 Cycle、经 RG 放回整体路线作抽象综合、判断关键处并选择下一步。这是同一根内的研究过程，阅读与思考随发现往返，资源整理和独立审阅沿下文职责穿插完成。可以没有新发现或保持原认识，说明原因与投入含义；Cycle 收口不表示 Question 已回答。

沿[本轮重心](../references/cycle-work.md#本轮重心)理解收到的原文与来源，对照优先投入与实际所得，判断当前安排是否仍值得继续；实际调整记入已有综合与 notes。

输出和来源见[语义契约](references/contract.md)；权限与接纳见[Owner 操作](references/owner-operations.md)。检索或复用时读[研究导航](../references/research-navigation.md)，安排投入或委派时读[研究指导](../references/research-guidance.md)。输入已有正文无需为固定顺序重复读取。

处理适用指导、主动材料或求助答复时，读[人类协作指导](../references/human-guidance.md)，将实际影响与仍待判断事项纳入综合。

## 1. 认真分析本 Cycle 的工作

先对照首轮的完整 Question、当前 Goal 与适用指导、本轮重心、完整 FormalPlan、Bundle 最终交接及每项实际工作的关键结果和限制，分清计划承担的回答责任、真正开展的工作及尚未获得的证据，联系结果与限制判断已有认识发生了什么变化。再围绕综合所需的问题展开准确原文和相关历史；首轮组织及读取触发见[上下文与准确材料](references/contract.md#上下文与准确材料)。保持 request、Question、Quest、Goal、epoch 和来源绑定。Idea／Plan／Bundle 的 Completed、Skipped、Exhausted、NoViableCandidate 是路线状态，本身不证明科学主张。

本 Cycle 阶段与 Target 的暂存说明及本工作已交付文件沿获授 Workspace reader 核对；加工、保管或跨 Cycle 文件交接读[材料与保管](../references/materials-and-custody.md)。这些材料可解释过程和未决项，科学结论的正式来源仍须核验接纳链。摘要尚未呈现的内容先沿准确入口核实，区分尚未读取与工作实际未产出。

比较历史结果时，将实验结论对应到实际产生它的 Cycle／ScientificOutcome，区分结果产生轮次与后来转述它的轮次。“上一轮”仅指当前 Cycle 的直接前序；较早试点写明来源轮次，尚未核实轮次时称“既有试点”，保留架构、数据和协议差异。独立审阅据这项对应关系核对比较措辞。

从冻结闭包、Plan 已验证来源绑定或同 Quest 可核验历史引用精确 kind／ref。LiteratureRecord、MetricResult、WorkProduct、日志、分析、checkpoint、人类输入、ScientificOutcome、AssetVersion 等按真实内容支持、反对或限定判断；材料类型和数量不决定科学采用资格。仍须核对 Owner、版本、Quest 权限和接纳链，不能用相近对象 ID 代替真实来源。纯理论综合可无外部引文，明确推导、适用范围和不确定性。

按事实选 `affirmed | denied | uncertain | insufficient_evidence`。affirmed／denied 限定 claim；uncertain 说明有效证据为何未收敛；insufficient_evidence 保持 `claim=null` 并说明缺失。部分证据与仍缺其他证据可以同时存在。未测量、科学证据不足、访问阻塞和程序故障分别表述。

用 `support_scope`、`limitations`、`causal_interpretation`、`research_synthesis` 和 notes 组织解释，短结论结合实际采用的精确来源。冻结可用来源和已知历史身份由系统携带，父问题的引用用于关联各自影响判断，具体输出边界见语义契约。区分事实未查清与风险受控、新认识与重复整理；反复无进展时重审缺口、策略或资源，而不是无理由生成新 Cycle。

聚焦阅读、历史召回和比较可委派独立子智能体，根抽查关键原文后综合。人类指导按真实内容影响判断，普通意见不自动成为授权或完成确认。完成条件：关键判断能追溯到实际来源，已有认识、局限和缺口明确，技术阻塞没有被写成科学结论。

## 2. 经 RG 审视整体路线与关键关系

每轮都将本轮所得放回当前 Question 的研究历程、同 Quest 的相关或暂放问题，以及整体 Goal 中审视。通过 RG 的 Question 视角及适用入口发现和展开所需积累；已有准确材料足够时直接判断，视野不足时主动扩大相关路线的读取。以这些材料比较当前工作的研究意义，按实际需要掌握范围与分页，不要求每轮遍历全库或固定调用次数。准确入口见[研究导航](../references/research-navigation.md)与[Owner 操作](references/owner-operations.md)。

从具体工作中抽象出影响路线判断的关系：例如不同尝试依赖的共同前提，观察与原有解释之间的矛盾，问题间的前置依赖，或多条路线受到的共同限制。将这些关系放回具体来源和适用条件检验，分清已有依据支持的认识、待检验的解释和仍未查清的联系。相似结果或同时失败本身不能证明共同原因；认识不变或只有证据缺口时也如实表达，不强造唯一主要矛盾。发现关联后可回读本轮或历史细节，修正前面的分析。

开展上述审视时，可以同时委派 1 个子智能体，提供当前 Question／Goal、本轮重心、关键材料及获授读取入口，请它按同样的方法独立审视工作关系、关键问题与矛盾；根 Session 同时继续自己的分析。子智能体返回判断、准确依据、适用条件和重要未查部分，根随后聚合双方认识，比较相互补充之处与实质分歧，必要时回读关键来源，保留尚未解决的不确定性，再形成整体判断与后继选择。最终取舍由根负责；这项并行研究协作与后文对完整草稿的独立审阅各按其职责进行。

用 `research_graph.question_relations.read` 读取相关问题。有值得保留的横向关联或重叠时，经 `research_graph.question_relations.record` 提交同 Quest 两个精确已接纳 `question_ref` 与说明；包含关系仍用原 `parent_question_ref`。同一 `effect_id` 对应同一内容，结果不明先 reconcile；关系不表示问题已解决。

完成条件：与后继取舍有关的路线和关系已有必要理解，关键判断能回到准确依据，重要未查部分及其影响明确。全局审视不是穷尽所有方向，也不把未经比较的局部下一步直接当作整体优先项。

## 3. 判断关键处并选择下一步

结合当前 Goal、人类指导、研究风格、历史积累和现实资源，判断澄清哪个关键问题或矛盾最能改变当前认识、推进重要目标或为后续工作创造条件。对实际比较过的重要方向说明取舍；不以最新失败、难度或新颖性自动决定优先级。尚缺作出路线取舍的依据时，下一轮可以先澄清关键不确定性。由此分别判断是否独立建题、选择哪个有效开放的问题、从哪个阶段开始，以及粗粒度研究重点。

先决定研究需要，再选 `idea | plan | reasoning`。需重新构思进入 Idea；构想仍适用且需要安排阅读、分析、准备或实施等工作时，以可验证 Idea skip basis 进入 Plan，由 Plan 重新选择义务、复用和剩余工作；已有材料只需综合时，在前序 skip 合同成立后进入 Reasoning。下一 Cycle 不直接进入 Bundle，旧 Plan 的 coverage 和 Brief 不替代当前计划判断。

说明完成了什么、剩余问题及后继理由，并引用相关结果或入口。继续研究时，结合实际进展与资源，在 NextCycleProposal 的 `cycle_focus` 写明下一轮重点做什么；既有 notes 交接已有判断与限制、未决问题、接续目的及选题和入口理由，保留实际前驱与准确来源。具体安排交由 Idea 与 Plan 展开，研究重心按[共享语义](../references/cycle-work.md#本轮重心)表达。跳过 Idea 进入 Plan 时指定一份准确的已接纳 IdeaSet，供后继首轮完整读取，保留原生产来源及本轮沿用依据；它可以早于当前三轮工作空间。Reasoning 的复用建议不等于正式输入绑定；Plan 选择义务和证据，Bundle 为具体 Target 绑定所需资产。同一 Question 可以继续研究，也可暂放、复盘已有问题或转向相关题，均说明依据。

建题线索可以来自 Bundle 推荐，也可以由 Reasoning 综合本轮结果、Target 原始说明及研究历史形成。读取已有推荐并核对依据；Bundle 未推荐、被跳过或因阻塞未完成筛选时，仍可自主判断新问题。按[新问题与后继 Cycle](../references/cycle-work.md#新问题与后继-cycle)区分保留线索、正式建题与下一轮选题。

先判断当前或已有 Question 能否清楚承载后续研究，能够覆盖的优先留在已有题中。确需独立追踪时，比较候选与已有题的区别、联系、独立价值及后续可开展的研究，选择最值得推进的一项进入建题流程。一次失败、待办事项或资源缺口的研究价值须结合实际依据判断；保留其余有价值线索，正式创建数量遵循共享规则，也可以决定不建题。

正式建题必须先走现有 AutonomousCreation 的 DeepFetch 路径，了解当前研究现状。取得标准 `summary.md` 后，本 Reasoning Session 读回精确摘要，结合已有问题重新评估独立研究价值，调整科学判断及待创建 Question 的完整六字段结构（按[共同语义](../references/cycle-work.md#新问题与后继-cycle)形成四项核心，`background_context` 与 `requirements_constraints` 按需补充、可为空），再决定 create／decline。已有题足以承载且无需独立追踪，或独立价值不成立时选择 decline，检索完成本身不要求建题；普通综合和补充阅读不强制该路径。新题可宽泛、具体、包含或关联已有问题，包含关系本身不排除有价值的分解；后续可继续认识其边界与可解性，正式正文按共享 Question 语义保持稳定。

创建前 AR checkpoint 只是不可变执行草稿，不预接纳 ScientificOutcome 或建题。DeepFetch summary 经 RM 接纳后，同一 Session 可修订结果与路线，也可放弃建题完成普通综合。只有决定 create 后才接纳唯一科学结果和修订问题，最后引用真实 accepted QuestionAnchor；failed／cancelled 且无 summary 时按事实决定 retry 或 decline，运行中或等人不算失败。恢复复用已有决定和接纳事实，不重复创建。

### 交接前整理已接纳 Target 资源

本轮 TargetCommit 身份从 context pack 的 `accepted_target_commit_closures` 读取，其中的闭包概要不代替候选正文；`predecessor_closure` 用于 `prior_accepted_bindings` 中的前序交接。候选读取、真实工作核验、精确内容与正式登记按[资源整理与正式登记](../references/materials-and-custody.md#资源整理与正式登记)执行。Target 已正式接纳即满足这些原件的发布前提，形成综合草稿时即可整理，不等本次 ScientificOutcome 接纳。

最后一个 Target 后 Bundle 若不再运行，由 Reasoning 承接。整理也包括 Target 过程中发现、取得或阅读的 Literature：沿用已有文献的准确身份，保留原文入口或尚未取得全文的状态、本次阅读判断及其研究用途，外部原作与本次分析各自保持来源。可委派明确资源范围的子智能体整理，根在交接前查回必要的资源记录、用途、精确内容及真实派生关系。无保留价值时说明判断；外部条件阻塞时记录未完成步骤和继续条件，未知登记效果沿原操作对账。现成资源的直接登记沿[研究导航](../references/research-navigation.md)的 Environment 分支判断；普通取得文献与 Target 阅读判断按共享研究导航的 Literature 登记、用途和准确原件 reader 处理，沿 Owner 操作查回结果。

收尾或向后继交接文件时，读[交接与工作区收尾](../references/materials-and-custody.md#交接与工作区收尾)，按共享生命周期安排后继读取、正式保管与清理。ScientificOutcome 草稿或单个 Target 完成不代表本轮已可清理，业务完成与执行、恢复、待接纳等依赖由正式职责方核对。

完成条件：值得保留且当前可登记的候选已登记并读回；空候选或无保留价值时说明判断，不制造资源记录；其余有真实取舍或具体阻塞说明，不把空 Dataset 身份当作已有版本，也不把登记当作新实验结果。

### 独立审阅并交接

委派原生独立子智能体检查完整草稿与关键原文，根根据自由格式反馈和自身判断修订最终内容，核对全局取舍是否有据、抽象关系是否被误作已证因果；没有具体问题也可改稿。同根自查不替代独立审阅，Owner 绑定内容 hash 并校验科研来源，不要求审查表单、审阅者身份证明或批准记录。

最终 transition 恰为 `NextCycleProposal | CandidateCompletion` 一项。前者选择已接纳且 present／open 的 Question／Anchor，给出合法入口、精确 skip basis 与非空 `cycle_focus`；等待外部条件时明确触发条件，并沿现有 HumanRequest／Owner 路径处理，不用重复 Cycle 轮询同一障碍。若等待使后继尚不能合理决定，保留待输入或具体阻塞，沿原根接续；唯一 transition 的要求适用于实际最终提交，不要求等待中交出虚构的后继。后者不含 `cycle_focus`，须有 Quest 整体目标和里程碑依据，并经人类明确确认及 Owner 接纳。字段与准确来源合同见语义契约。

提交前按语义契约核对实际采用的引用及各问题影响，输出一份简短、完整闭合的 JSON。收到截断、引用或身份冲突反馈时，在同一会话回到指出的精确对象修正后重新提交完整结果，不沿未闭合字符串继续重复引用或拼接多份结果。

完成条件：科学结果、沉积状态和唯一后继选择清楚，notes 进入正式闭包供下一轮使用；由 RM／RG／AR／AE 接纳链推进。未知结果先对账，必要输入或 currentness 故障保留具体阻塞；仅经公开 Owner 接口操作，不读写私有数据库、spool、seal key 或控制文件绕过边界。
