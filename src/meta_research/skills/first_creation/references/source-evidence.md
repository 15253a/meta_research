# Source evidence

Registered server references are entrances, not captured input files. `research_workspace.materials.discover` lists the visible references or expands one directory. Discover the requested path to obtain its `observation_ref`. `research_workspace.materials.read` accepts `reference_ref`, `path`, `observation_ref`, `offset`, and `max_bytes`. Each read returns at most 65536 bytes and an opaque `read_witness`. The witness records the exact observed source and byte interval. A citation contains `witness_ref` and an actual section or line description in `location`. New consumption uses witnesses from this current operation. Do not invent witnesses or treat browser reads and earlier operations as current consumption.

A reassessment names the supplied exact `predecessor`. Its `decisions` covers every prior statement once. `retain` preserves the original text, kind, conditions and citations. `replace` names new `replacement_refs` in `additions`. `needs_recheck` and `out_of_scope` record `affected_scope` and `creation_limit`, either `required_first_question` or `future_research`. Each decision records `applicable_conditions` and an explanation. `additions` contains all six groups for new statements only, complete current coverage and genuinely new selections. Excluded statements remain readable in applicability and do not remain supported current claims.

Choose `inherited_evidence` only from the supplied evidence facts. Each `witness_ref` appears at most once. Use eligible `live_source` for current reuse, with `selected_material_key=null`. The Owner rechecks its original observation and range bytes against current entrances. It retains its original `operation_ref`; this is no new read. Use `managed_history` only for historical support, naming the original witness and an exact `selected_material_key` also listed in `inherited_selection_keys`. Never emit both kinds for the same witness. Managed history cannot enter current coverage or prove a changed live file was read. A stale linked locator or unretained source cannot guarantee historical bytes remain available. An old basis hash still identifies that history.

Use `inherited_selection_keys` to reuse eligible exact selected versions independently of witness disposition. For an unchanged file in managed custody, inherit its eligible witness once as `live_source` and retain its selected version here. Managed custody does not require a second `managed_history` entry for that witness. Do not put those old selections into `additions.selection` for another intake. Only new selections use current OriginalFile or WorkFile selectors. State historical limits beside affected claims and preserve unread scope.

Coverage includes every registered entrance. Its `material_key` is the exact `reference_ref`. Each coverage record contains `kind`, `read_ranges`, and `unread_description`. `read_ranges` contains witness citations. Use `read` only for a file whose observed ranges cover all bytes. A directory is `partial` or `unread`, because discovery does not read its files. Use `partial` with the actual observed ranges and describe the unread scope. Use `unread` with no ranges and a truthful entrance description. Claims about content need observed sources. Composition, gaps, and unfinished questions can describe an entrance or a missing source without claiming its content. Conditions stay beside the claim they qualify.

`research_workspace.materials.copy` accepts `reference_ref`, `path`, `observation_ref`, `effect_id`, and `max_bytes`. It copies one observed file into independent writable work. The default limit is 1 MiB and the maximum is 8 MiB. The receipt names the `work_file`, `working_path`, and `read_witnesses`. Retry the same `effect_id` with unchanged arguments or use `research_workspace.materials.copy.reconcile`. A retry does not overwrite an edited copy. Native reads of work files and trial outputs are not MCP input witnesses.

A selection contains `source`, `custody`, and `reason`. An `OriginalFile` source contains `kind="original_file"`, `reference_ref`, `path`, and `observation_ref`. A `WorkFile` source contains `kind="work_file"`, `work_ref`, `path`, and `trial_ref`. Use the `work_ref` from the execution binding and a path relative to this operation's work directory. For a copied file, use the receipt's `work_file`. `trial_ref` is the copy `effect_key` or `null` for a new result. Choose `managed` or `linked_local` custody for each exact file. Select originals and results separately to retain both, or return an empty selection to retain neither.

Formal custody applies only to selected content. `managed` custody preserves the selected bytes. `linked_local` custody retains a readable locator for the exact version and reports later source drift. Selection does not issue an acceptance receipt or manufacture research execution. Original producers, external paths, and imported results remain external provenance. Unselected originals remain available through their references and can later report changed or unavailable bytes. Unselected work files do not enter formal automatic saving.

Legacy `material_manifest` entries apply only to explicitly captured paths. Each legacy citation contains `material_key`, `offset`, `length`, `chunk_sha256`, and `location` for bytes actually read through the bound native workspace. The Owner checks those bytes. Legacy selection names `material_key` and `reason`. Do not construct a captured manifest for new server references or use legacy citations in place of returned read witnesses.
