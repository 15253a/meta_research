# Cycle 工作与 Quest 目标演化

安排阶段接续、发展研究问题、选择后继工作或重审整体目标时使用本文。研究既追问怎样继续，也追问为何继续。阶段组织使实践能够积累，目标演化使研究能够根据所得证据修正自己的追求。

## 当前 Cycle 的工作与交接

| 职责 | 推进与交接的重心 |
| --- | --- |
| Idea | 形成值得尝试的构想，说明依据、适用条件与未知。 |
| Plan | 判断已有支持与本轮投入，组织值得开展的工作及承诺，保留未安排责任与理由。 |
| Bundle | 在正式计划内安排并协调 Target 的具体工作，组织接纳与结果整理；正式接纳由 Owner／RG 完成。 |
| Target | 自主完成具体研究，交接实际工作、产物、结果解释、支持范围、限制、未决事项与新线索。 |
| Reasoning | 综合本轮认识，反思问题与目标，安排后继研究。 |

将阶段分工用作组织这一天的参照，结合实际研究灵活安排活动、工作组合与投入深度。可以实施、补充理解、复核旧判断、总结过去研究，或发现路线不通；本轮的重心与节奏随问题、认识和反馈发展。已有认识、失败和未决事项都进入判断，正常经过 Reasoning 综合收口；交接使后继理解真实工作、必要依据、完成情况及接续需要。

Plan 正常接收本 Cycle 前一 Idea 阶段正式接纳的一份完整 IdeaSet，包含其中全部 Idea。跳过 Idea 时，沿前驱 Reasoning 指定的准确绑定使用沿用的 IdeaSet；其最初产于更早轮次，也不因 Workspace 滑窗失去正式输入身份。近期及更远的其他 IdeaSet 按需要读取，不自动汇总进首轮。无论是否经过 Idea，仍适用的前驱 Reasoning 交接随本轮输入接续，IdeaSet 的生产来源与本轮前驱分别保留。

合理的阶段跳过沿对应合同处理：沿用仍适用构想时，可按 Idea skip basis 进入 Plan；Idea 正式报告没有可行构想，或仅需综合已有材料时，按相应跳过依据进入 Reasoning。Plan 完成有依据的规划判断并正式接纳后，Brief 非空则进入 Bundle，Brief 为空则由 AE 形成 Bundle skipped，进入 Reasoning；空列表既可对应全部 covered，也可保留本轮不安排的真实 gap，不表示所有责任或 Question 已完成。未安排理由、混合安排和仍需外部条件才能判断的边界见[Plan 合同](../plan_stage/references/contract.md#brief-与后继)；该路由沿已接纳完整 Plan 与实际 Brief 处理，不新增 Plan NoViable 或第三种 coverage。后继入口为 Idea、Plan 或 Reasoning，所需计划重新判断。需要重做上游构想、计划或改变已承诺的核心科学语义时，经 Reasoning 安排后继 Cycle；技术重试、恢复和补交文件接续原工作。投入与委派见[研究指导](research-guidance.md)。

## 本次阶段定位

运行时组织每次业务 `user` 输入时，在正文开头直接写明：“当前你处于第 N 轮 Cycle（准确身份）的 Idea／Plan／Bundle／Reasoning 阶段。当前 cycle focus 是：‘本轮重心原文’。”身份、阶段和重心来自本次请求绑定，重心的实际来源随输入保留。轮次使用该 Cycle 在所属 Quest 权威历史中的既有顺序；未提供序号时显示准确身份，不从名称或 ref 尾数推算。

首轮、同根续轮、新 native 及恢复输入均保留这段简短定位，随后提供本次任务、变化与必要依据。续轮继续按增量组织正文，普通工具返回不为重复定位而新增 user 消息。运行 phase、dispatch、target-batch 或独立审阅不另算 Cycle 阶段；恢复旧操作仍显示其原绑定，不能用全局 current／latest 重写历史输入。

Target 的定位说明“在本 Cycle 的 Bundle 阶段执行 Target（准确身份）”，同时给出同一重心；其具体义务保持冻结任务与合同。独立助手、Writing 和创建准备说明自身工作身份，不编造所属 Cycle 阶段。首个 Cycle 尚无已形成重心时明确显示“尚未形成”，带入已提供的准确起步意图，再依下节规则形成并交接；其他缺材按实际缺口处理。

这段定位是现有绑定的阅读呈现，不新增 Cycle／focus 权威、版本台账或冻结科学合同字段。实际重心的形成、来源和跨阶段继承按下节执行。

## 本轮重心

`cycle_focus` 是 Reasoning 在 NextCycleProposal 中写给下一轮的粗粒度研究重心，主要说明这一轮重点做什么。Reasoning 结合实际所得、研究需要与可用资源，选择一轮适合承担的重点；复核、重新审视已有工作，以及阅读、分析、准备、实施等都可以成为重点，按研究需要选择。

具体研究切入与计划安排由 Idea 与 Plan 结合当时材料展开，Bundle 与 Target 继续按既有职责决定实际组织和实施。选择重心所依据的认识与限制随既有科学交接保留，共同工作原则沿共享指导执行。各阶段据此组织本轮活动，对照重点与实际所得调整判断；重心不对应固定 24 小时、工作数量或当轮完成配额。

正常后继中，当前 Cycle 各根会话的首次模型输入直接带入上一 Cycle 的 Reasoning 为本 Cycle 给出的同一份原文与正式后继来源：正常经过 Idea 后仍交给 Plan，跳过 Idea 或直接进入 Reasoning 时也保留。Target 将原文作为任务说明，工作义务与边界仍来自 Bundle 冻结内容。技术恢复沿同一来源继续；同一 Cycle 的实际取舍记入现有 notes、StrategyUpdate.notes 或 Target research-note，不另建 focus 修改版、偏离台账或调度状态。

首轮没有前驱 Reasoning，沿创建或启动输入的准确来源使用起步意图；未提供时由首个根形成简短重心，写入本阶段既有 notes，随阶段交接传给后续根。首根无须为此另写详细计划或补跑 Reasoning。这是首轮工作的真实来源，不补造 NextCycleProposal；首次 Reasoning 后进入正常后继交接。

重心组织投入，不改写 Question 的目标、范围与回答责任，也不扩大授权或替代有效人类条件。发现原有判断不合适时，在实际工作中说明依据；越出当前问题范围时选择适合的已有题或按既有流程新建题，涉及整体目标变化时按正式 Goal 演化处理。各阶段按所得证据简要反思当前安排是否仍值得继续，无需另设质疑表单或提前综合状态。

## 新问题与后继 Cycle

**Question 稳定承载可跨 Cycle 持续研究的核心问题与目标。** 采用四项核心加两项按需补充，保留六字段结构，不以六项均有正文作为完整性标准：`title`（稳定导航名）、`unknown_statement`（核心研究问题与目标，不限于二元命题）、`answer_shape`（回答责任：希望形成什么认识、判断或产物）、`applicability_scope`（对象、适用条件及排除项）为四项核心；`background_context`（按需提供建题缘由与背景，不作逐轮研究日志）、`requirements_constraints`（按需提供改变题意的额外要求，无实质要求时可为空）为两项按需补充。慎用回答责任与约束：真实存在且适用的题意要求不能遗漏，但普通工作原则、评价建议、方法偏好、运行授权及整体 Goal 沿各自入口生效，不复制或升级成 Question 的永久硬约束；不用报告格式、实验步骤或指定方法代替科学回答，不凭空固定无依据的证明门槛，题意或约束强度不清时保留实际不确定性；不预定正结果，正、负或不确定结论均按实际依据判断是否履行回答责任。Question 保持相对稳定，无同题正文版本管理或复杂质疑机制；方向实质改变时切换或新建问题。上一 Cycle 的 Reasoning 为当前轮提供粗粒度 `cycle_focus`，仅说明本轮重点做什么，具体切入与安排交由 Idea 和 Plan 决定；首个 Cycle 沿既定起步意图。

各阶段保留新线索、依据及其与已有问题的关系；Bundle 可以跨 Target 汇总并推荐。Reasoning 也可以根据综合结果自行提出新 Question，无须等待 Bundle 推荐。先判断已有 Question 能否承载，再判断独立建题的价值；每个 Cycle 的自主研究流程最多正式新建一个 Question，也可以不建。

具体建题调查、DeepFetch、候选比较和后继入口按 [Reasoning Skill](../reasoning_stage/SKILL.md) 展开，由 Reasoning 综合调查结果作出判断。首题及人的手动创建沿各自创建职责处理。

**建题与选题分别判断。** 创建一个问题，说明它值得独立积累；下一轮做什么，还取决于当前价值、证据缺口、依赖和资源。下一 Cycle 可以继续当前题、回到其他已有题或攻克新题，选择同一 Quest 中正式有效且开放的问题。新题成立不自动使它成为下一轮重心。

## 正式 Quest 目标演化

**目标是研究的方向，也是研究的对象。** 实践可以使整体问题和完成标准更清楚，也可以揭示初始假设、范围或价值判断需要修正。人的正式指导与 Agent 自身积累的研究证据，都可以成为演化来源；有价值的结果可以不同于最初设想。

Idea、Plan、Bundle、Reasoning 和 Target 根均可在职责内正式演化目标，不必等待 Reasoning。发现足以重审方向的依据时，结合当前完整目标、完成标准、持续条件和工作的实际状态作出判断。Reasoning 仍负责本轮综合和后继安排。研究风格影响探索与转向的取舍，仍有效的人类持续条件继续继承；人的要求及其确认范围见 [指导涉及整体目标](human-guidance.md#指导涉及整体目标时)。

**演化需要说清改变了什么，以及为何值得改变。** 正式提交新的整体目标、完成标准、变化理由、证据及对现有工作的影响。未变条件沿有效基准继承；目标版本与历史依据保留，让后继能够理解旧选择如何通向新判断。

继续有价值的工作，需要调整或停止的工作由系统实际协调，并保管应留下的内容。以正式结果确认新目标版本生效和受影响工作的实际处置；未解决的分歧与尚未完成的处置如实保留。提出目标、表达停止意图与实际生效分别依据其事实判断。

方法与投入调整、Question 分解或新建、后继选题、正式目标演化可以相互促成，但分别判断，不自动要求同时发生。独立助手、Writing 和创建准备沿各自职责工作；本节不为它们增设 Cycle 调度或正式演化权限。

## 目标演化的准确操作

调用 `research_graph.quest_goal.read` 读取当前整个 Quest 的目标、完整完成标准、持续条件、指导对齐状态，以及本次已认证逻辑操作冻结的实际工作切面。该切面在同一操作内不可更改；新 Target、生命周期或运行条件使它过期时，保留 stale 结果，由新签发的根操作获得新切面，不刷新旧调用。

用 `research_graph.quest_goal.evolve` 以一个判断同时提交替换目标和完整完成标准、对每条现有持续条件的保留或精确人类替代、对冻结切面每项工作的安排，以及后续方向。科学原因要么是本操作已取得准确原文、确认范围覆盖 Quest 的精确指导 delivery，要么是已接纳且在 RG 中有本 Quest 用途的精确证据版本。局部指导不能充作整体变更授权。研究 Agent 仍可结合研究风格，基于接纳证据自主演化；此证据原因保持独立，无需新增助手或人的一律确认。持续条件只能由更新、已取得完整原文且适用整个 Quest 的人类原文精确替代；后续的证据驱动演化仍继承它们。

工作安排覆盖 read 返回的每个可行动句柄：继续价值工作，在根阶段边界结束当前阶段，阻止未启动 Target，或停止精确 Target/run/generation。每个 stop 同时给出产物保留判断：`selected` 仅引用已经 RM 精确读取、managed 保管且 RG 有用途的真实产物；`pending` 明确后续要审查的工作区；`inspected_none` 说明已检查而无需保留。Target 工作区的规范说明可先用普通 Asset intake 的 `target_workspace_note` 选择器按原始字节接纳，再经 RG 作用关系选入；取消本身不伪造 Run、Evaluation 或完成产物。

effect 不确定时，用相同 `effect_id` 和字节等价判断调用 `research_graph.quest_goal.evolve.reconcile`；不改动 effect_id 重做。成功演化之后，系统以实际 AR 结果异步执行停止或阻止；Agent 不把意图当作已完成。

## 交接的实际来路

任何阶段、Target 或跨 Cycle 入口都先读相关交接：为什么继续、尝试过什么、哪些失败或未决、当前研究范围、选用的精确资产，以及需要遵循的人类意见。用现有 notes 或研究正文保存会影响下一步的判断，并引用原版本；简短说明与读取入口随交接提供，完整历史按需展开。收到人类答复后，保存 request_ref、response_ref、所采纳意见及其对工作安排的影响；后继可通过 human_request.read 读取当前 Quest 的分页请求记录或精确回复。请求状态、回复和正式授权各自保持实际含义，人类建议不能冒充实验结果。技术恢复细节保留在日志，仅简述对研究有效性或后续动作的影响。
