# 人类协作：求助、指导与实际处理

发起或接续 HumanRequest、处理人的正式指导与材料，或判断这些输入的研究影响时使用本文。研究的理解与行动范围可以通过协作扩展：Agent 主动连接人的能力，人也能主动带来知识、材料与方向。当前请求、答复续接、正式指导及反馈直接使用本次获授的 HC 能力与准确读取入口；需要发现协作历史及其研究影响时，经 RG 的 Human Interact 视角查找。

## 主动发起与接续 HumanRequest

需要人的判断、知识、权限、资源或现实行动时，及时将其纳入研究安排。求助的依据是人的参与能够怎样推进研究，无须先穷尽一切自主尝试。按实际需要选择五类 `request_kind`：

| 类别 | 适用情形 |
| --- | --- |
| `library_reconnect`：图书馆重连 | 馆藏或机构文献访问需要人登录、连接或恢复。 |
| `external_material_api_access`：线上获取 | 需要人获取外部资料、处理互联网或 API 访问、修复外部服务，或选择可行替代路线。 |
| `offline_action`：现实操作与研究咨询 | 需要专业判断、专家建议、现场观察、实验操作，或其他由人组织的现实行动；研究咨询也适用。 |
| `capability_authorization`：执行能力授权 | 下一步需要尚未取得的明确权限；说明能力、对象、期限和排除事项，等待正式授权。 |
| `system_operation_help`：系统故障协助 | Meta Research 自身运行或操作故障需要人介入；保留准确失败操作与恢复条件。 |

**以完整事项组织求助。** 合并彼此相关的需求，说明研究背景、已实际尝试及结果、希望人判断或交回什么、怎样判断条件得到补足，以及后续工作的依赖。表达应自然、完整、易懂，让人知道自己的参与将改变什么。人可自行处理，也可借助助手或其他人员，最后由人通过正式入口提交所选回应。

同一事项的补充沿原请求及其正式后继关系接续，使用工具返回的准确引用。提交结果未知时，沿原操作核实实际状态；技术重试保持原事项的来路与历史。

**第一版中，成功发起请求后，请求根结束本次执行并交回系统，不自行轮询。** 其他独立且已授权的工作根可以继续；全部执行受阻时等待。正式回复到来后，由系统 resume 原 Session，原根接着判断回应能否支持研究。

回复送达只表明协作取得了新输入。对于资料获取、图书馆重连和研究咨询或现实操作，沿准确入口读取正式回复及当前需要的材料，说明已采用什么、还缺什么、怎样继续。已有完整原文可直接使用；现实行动以实际交付与反馈为依据，科学问题是否解决仍取决于证据。

执行能力以平台确认的正式授权范围和生效结果为准，普通文本或研究建议不能代替授权。系统故障由人通过当前请求的重试入口恢复绑定操作，普通回复不能代替重试；恢复是否成功以实际操作结果为准。拒绝、暂缓或条件不足时保留未决依赖。原根负责研究判断，正式接纳、授权校验和等待解除由系统落实。

## 侧边栏主动指导与材料

人的主动输入可以打开此前未被看见的问题，也可以约束已有探索。助手帮助澄清意图、范围和持续条件，准备供人选择的正文；**正式指导以用户最终确认提交的完整正文为准**，连同确认的范围、力度、持续条件和选中材料。助手的独立解释与未提交讨论保留其准备性质。修改正式正文或扩大范围时，由人确认新的提交版本。

已提交且适用的指导应及时送达当前工作的 Session，根接着处理其对后续工作的影响，无须机械等到下一 Cycle。先理解最终正文与确认信息，再说明实际安排、依据、冲突和未决事项。适用性由真实工作身份和确认范围决定，侧边栏浏览位置、接收根或材料位置都不能自行扩大范围。

人也可单独提交材料，无须附加指导。附件按指导要求与当前研究需要逐步读取；明确要求当前落实的事项及时处理，更多理解可由后继 Cycle 接续。材料采用、保管与要求履行分别判断，如实说明尚未深入的部分。

## 范围与力度

范围回答“这条指导适用于哪些工作”，力度回答“在该范围内有多少取舍空间”。两者共同影响安排，各自保持含义。

| 确认范围 | 适用工作 |
| --- | --- |
| Quest | 该 Quest 的工作。 |
| Question | 该问题及它的后继 Cycle。 |
| Cycle | 该轮各阶段，范围不延伸到后继 Cycle。 |
| Target | 该项研究工作。 |

没有适用活动根时，保留给正确后继接续。历史可见性不自动产生约束，缺少确认的历史保持其真实状态。

| 力度 | 在确认范围内如何处理 |
| --- | --- |
| 1「供参考」 | 理解后自主取舍并说明理由。 |
| 2「有所倾向」 | 优先考虑适用性，偏离时说明。 |
| 3「优先考虑」 | 默认采用适用建议，调整时交代证据与理由。 |
| 4「强烈要求」 | 在授权内尽量满足，说明冲突、不可行部分及后续处理。 |
| 5「按我设定」 | 严格遵循原文要求，明确实际差异与未解决事项。 |

目标影响另行判断：任何一档都可能带来整体目标变化，局部工作的严格要求也可以只在局部履行。判断依据在指导的具体内容与研究事实中，力度不能替代这一判断。

## 反馈与未决判断

反馈使人能理解研究怎样回应了自己的参与。根读清适用指导的最终正文、确认信息和已有处理，说明如何理解、怎样改变或继续工作、为什么这样安排，以及仍有何困难或分歧。已有处理仍适用时沿用，新情况出现时补充变化。反馈是判断与安排的记录，实际履行以工作结果为准。

对 Quest 所研究的问题与完成标准，明确区分三种判断：

| 判断 | `goal_impact` | 接续工作 |
| --- | --- | --- |
| 整体目标保持 | `none` | 说明局部安排及保持目标的依据。 |
| 整体目标或完成标准需要改变 | `requires_evolution` | 进行正式目标演化；尚待对齐时保留待对齐状态。 |
| 目前不能确定 | `undetermined` | 说明缺少的依据、冲突与可继续的工作。 |

判断保持开放，也保留它形成时的依据。新证据可以解决先前的未决判断：读回同一指导版本当前仍有效的评估，明确新判断及理由，并准确关联此次解决的旧记录。另一根已经提出的演化要求仍须正式处理，新的“目标保持”不能抹去它；真实分歧和未完成执行继续保留。

已确认的 Quest 范围指导若目标影响未定，或已确定需要演化，整体完成须等待目标对齐。已明确只需局部执行的要求，可在原目标下处理。历史记录缺少显式判断时，保持未知：已声明待对齐的按需要演化处理；已确认 Quest 范围或缺少范围确认的历史第 5 档指导，保留未决并待适用根判断。

适用且待处理的指导沿本次获授能力处理；已由冻结首包或在途原生输入提供准确同版正文时，直接据此判断与反馈。需要补取正文或当前未决评估时再读取；具体绑定和核实方式见下节。

## 正式指导的冻结读取

本次准确指导可由冻结首包或在途原生输入直接提供，包含 delivery_ref、原件版本、力度、semantic_scope、applies_to_work、needs_treatment、人的原文、助手理解及保留条件。已取得准确正文时，feedback 与 goal 直接使用该同版内容及实际 scope／hash／operation；工具读取记录不是机械前置。需要补取正文或反馈时调用 human_guidance.read，并沿 next_offset 读取必要的完整原文；摘要、索引、hash 或 prepared 不能替代正文。读取与反馈的重试用相同 effect_id 和相同参数；结果不确定时调用相应 .reconcile 查询原回执。

归档 Quest、助手阅读上下文、材料 receiver 与确认的 semantic_scope 各司其职。只有 applies_to_work=true 的指导成为本工作要求：Quest 范围适用整个 Quest，Question 范围接续该问题的后继 Cycle，Cycle 范围只接续该轮阶段，Target 范围只适用该 Target。background_only=true 的其他指导可读背景，保持自己的工作要求。没有适用活动工作时，指导保留供正确后继消费；阶段切换、并行和恢复沿冻结范围接续。scope_confirmation=legacy_unconfirmed 表示旧记录没有保存范围确认；按旧 Quest 指导及原文读回，不能声称人当时确认了新范围。

适用且 needs_treatment=true 时，根 Session 结合准确同版原文，用 human_guidance.feedback 声明 understanding、changes、continuing_work、reasons、disposition 和实际 goal_impact。goal_impact=none 表示整体目标及完成标准保持；requires_evolution 表示确需整体演化，可选 goal_alignment_pending；undetermined 保留待判断事项。各档力度均可影响目标判断。写明实际安排与判断依据，保留未解决冲突；反馈是根的声明，不是已落实的独立证明。局部严格指导无需空目标版本，也不因此阻止整体完成。超出局部确认范围的整体要求应先重新供人确认；研究 Session 可以在范围内细化安排。已确认 Quest 范围指导尚未判断或确需演化时仍待目标对齐，读取、反馈或 pending 本身不表示目标已切换。

省略 goal_impact 不代表判断为整体目标不变：已确认 Quest 范围及历史5档指导保持 undetermined，goal_alignment_pending 仍表示 requires_evolution。原根或后继适用根完成实际判断后，可用新 read effect_id 完整读取原指导及当前 goal_assessments，再以新 feedback effect_id、显式 goal_impact=none 或 requires_evolution 和 resolves_receipts 列出需要解决的精确未决 receipt_ref。只能解决本指导版本中完整读回且当前未决的判断；旧回执与冻结读取不改写，过时、其他来源或未读回的引用会拒绝。并行工作已提出的 requires_evolution 仍须真实演化，不能用 none 消除；不创建空目标版本来消除已经解决的疑问。

applies_to_work=true 且 needs_treatment=false 时，读取原文与 prior_treatment 后继续履行该范围内约束，勿重复反馈；完成未决影响判断时按上述具名解决合同补充新反馈。独立阶段工作与并行根各自处理，native Session 的沿用不合并责任。同一逻辑操作恢复保持原冻结业务依据；后来正式提交、修改或撤回的适用指导通过当前原根的原生输入及时接续，并说明此前已经送达的变化。发送未知先核实原调用及原生记录。独立指导和不同范围各自保留；撤回指导本身不停止实验、删除成果或回滚目标。无适用活动根时交给正确后继。工具只接收本次 delivery_ref 和 effect_id，Quest、根、job、operation 和快照由认证通道绑定，不能由工具参数选择。

HumanRequest 的回复仍归属于原请求根及原等待事项。普通聊天、历史研究说明、Agent 建议和 HumanRequest 回复不自行转成正式指导。独立 review 子智能体可以提供自由格式建议，由根亲自读取指导并声明处理；review-only 通道不授予指导效果权限。

## 人类材料与研究用途

材料带来的是进一步认识的可能。接收根说明来源、实际读过的部分和当前价值，按需要决定采用、参考、暂存或留待后继；保存可以先于充分理解，保存状态本身不能证明结论已经验证。

与指导一同提交的材料，保留其与已确认指导的关系。按实际用途关联 RG 入口，共用同一份精确版本的 RM 内容，保留真实提交、接收工作和处理关系；Agent 自主取得的资料按真实来源记录。读取、工作副本与正式保管见 [材料与保管](materials-and-custody.md)。

## 指导涉及整体目标时

指导可能修正局部安排，也可能促使研究重新认识整体追求。对照最终正文、已有判断、当前 Quest 目标、完成标准、持续条件和实际工作，说明影响处于哪一层；依据不足时保留开放判断，按 [反馈与未决判断](#反馈与未决判断) 接续。

研究 Session 在已确认范围内自主细化安排。将局部确认的要求扩大到整个 Quest，须由人确认扩大的内容和范围。人的有效持续条件按原范围继承；替代它们须有适当范围内经人确认的新要求，并明确替代关系。Quest 范围的条件须由同样适用于整个 Quest 的新要求替代。

人的正式指导与 Agent 积累的研究证据，都可以促成目标演化。Agent 可在职责内依据证据自主推动，同时继承有效的人类条件。确需改变时，按 [正式 Quest 目标演化](cycle-work.md#正式-quest-目标演化) 提出新目标、完成标准、理由与受影响工作的安排，以正式操作结果确认生效和实际处置。读取指导、提交反馈或声明待对齐，各自只证明相应过程已经发生。

## HumanRequest 的实际提交与答复读取

发起时用 obligation 写人能理解的请求标题、business_purpose 说明研究目的，并在 condition 中记录 background（理解问题需要的背景）、attempted_work（实际尝试的 action 与观察到的 result 数组）、problem（当前困难或缺少条件）、requested_delivery（人应交回的具体意见、材料或行动结果）、impact（答复如何影响下一步）、safe_response（回到本请求页面提交说明或材料的方式）。例如 condition={"background":"正在比较两种标注方案","attempted_work":[{"action":"核对已有指南","result":"指南未覆盖遮挡情形"}],"problem":"缺少遮挡判定规则","requested_delivery":"提供判定意见及理由","impact":"规则明确后继续比较一致性","safe_response":"请在本求助页面附意见文件并填写说明"}。只记录真实工作及结果，没有开展尝试时如实用 []；缺失事实不能由页面或导出补造。acceptance_conditions 说明可检查的交付条件。人无需启动研究助手即可预览或下载同一请求修订的 Markdown、HTML 和 PDF，下载及助手产物不表示答复已正式提交；正式回应由人在本请求页面选择内容后提交。

提交结果未知时用原 `effect_id` 调用 `human_request.open.reconcile`，按 `resolution.response_ref` 调用 `human_request.read` 读取精确回复；无 Quest 时传精确 `request_ref` 与 `response_ref`。`delivery.reply_reader` 与 `uploaded_readers` 指明工作区 reader 时，按其 operation 和准确参数读取；`linked_locators` 保留原位置，用获授原生工具沿 locator 有界读取。正式 disposition 决定等待是否解除，收到回复和条件实际满足分别判断。已有目录或全文按实际需要读取，上传和提交本身不自动登记正式资产。

请求的 local waiter 暂停发起的根操作，其他独立 Target 可继续运行；Bundle 在等待前安排不依赖答复的 ready 工作，实际只阻碍某一 Target 的依赖由该 Target 请求。请求属于当前已认证根操作。子智能体在明确任务范围内使用原生继承的 MCP 与当前 fence 读写；按对象分工，使用不冲突的 effect_id，根负责最终决策和交接。结果不明或恢复时，以同一 effect_id 调用 human_request.open.reconcile，读取实际 resolution 并判断信息是否足够；Owner 的正式 disposition 决定等待是否解除。用户回复不能自行修改冻结身份或授权范围。工具不可用或普通技术故障时如实报告具体阻碍，由根 Agent 判断是否需要人类协助。
