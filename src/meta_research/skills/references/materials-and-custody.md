# 工作材料、正式保管与交接

接收、阅读、加工、保管材料或整理工作区时使用本文。积累来自实践，也需要取舍：保存让后继能够接续，清理为新的探索留下空间。围绕研究用途安排材料的生命周期，使保存价值与磁盘成本相称。

## 文档与读取位置

可访问、已阅读、已采用、已保管和已验证分别代表不同事实。材料进入视野，只意味着多了一种可能；它能支持什么认识，仍需通过阅读、使用和检验逐步判断。

工作规则由指定 Skill、合同和操作说明提供；当前目标、Question、计划及上游结果说明研究从哪里继续；正式资产沿精确版本和读取入口使用；草稿、缓存与工作副本由 Workspace 承载。已有准确正文、路径或 reader 时直接使用，按当前需要补足缺失内容。核对公共材料 intake、正文 reader、分页或错误时，读本文的[准确读取与错误](#准确读取与错误)及[工作资料的当前处理与后继交接](#工作资料的当前处理与后继交接)；实际参数、返回和错误合同沿[当前获授工具与准确入口](research-navigation.md#当前获授工具与准确入口)按需取得。目录位置和相邻文件本身不赋予正式输入或证据身份。

创建 Quest、手动创建 Question、主动指导和 HumanRequest 回复提供的目录，在整个 Quest 内按当前授权只读访问，不受临时 Workspace 三轮窗口限制；原接收工作关系不随后继根改绑。每次访问重新核对当前权限和真实位置可用性，撤权、离线与路径变化如实反馈。按需从原目录读取，需要编辑、解包或试跑时，复制关键部分到当前工作的 Workspace。主动指导和求助回复上传的小文件进入对应 Workspace，按实际接收工作保留来源。

挂载或收到材料后，由 Agent 判断何时理解、使用和登记。当前研究需要决定阅读范围和副本规模，无须立即全量扫描、读取、复制或登记。人提供的只读原目录保持其原件性质。

## 阅读、工作副本与保管选择

**理解逐步形成。** 先读当前判断所需的部分，结合探索反馈再决定深入、验证或委派。材料可以部分读取、暂存或交给后继 Cycle 深入理解；说明实际读过什么、尚未理解什么以及当前判断的边界。明确要求当前落实的事项及时处理。

**保管服务于用途。** 自主选择保留原件、处理结果、两者或均不保管。保存原件可以先于充分理解，选择理由应体现保存价值；已保存不证明内容已经验证，已制作副本也不证明它已成为正式资产。保护昂贵、不可替代或难以再次取得的内容，复用已有精确版本。

RM 提供两种保管方式：

| 方式 | 选择时理解的事实 |
| --- | --- |
| `managed` | RM 管理所选内容的独立副本及精确版本，承担相应复制与存储成本。 |
| `linked_local` | RM 正式保管所选内容的本地读取位置及精确版本关系，保留该文件；这种方式本身不产生独立备份，来源漂移或失效如实呈现。 |

正式原件保持原位、按准确版本读取。需要编辑时另建工作文件，只复制本次需要的内容；按材料选择或 Target 正式交接接纳新文件及其来源，旧原件仍保持原版本。直接改写 `linked_local` 原件会触发漂移，恢复执行也不改变这一边界。

综合研究用途、体积、复制成本、位置可靠性和后续使用便利选择方式。正式保管以工具确认的结果、版本和可读入口为依据，尚未成功或结果未知的部分保持未决，按当前合同核实；长期内容与临时内容的清理边界见 [交接与工作区收尾](#交接与工作区收尾)。

## 资源整理与正式登记

整理使经历过的实践成为后继可以理解和复用的积累。按研究价值选择保存内容、登记时机与关系粒度，让输入、实际工作、产物、判断和用途相互关联。需要什么研究关系，取决于本次形成了什么认识与内容。

### 按六个研究入口组织积累

| 入口 | 保留的研究含义与关系 |
| --- | --- |
| Question | 当时的问题与目标、实际工作、认识、失败、负结果和未决事项。 |
| Baseline | 方法、具体方案、真实执行、输入与产物，以及适用的评价和反馈。 |
| Literature | 文献身份、原文、实际阅读判断、支持的主张、分歧及采用背景。 |
| Environment | 资源身份、来源、能力、已知条件、描述快照、适配来路与用途。 |
| Dataset | 数据身份、精确版本、来源、处理与派生关系、具体用途和局限。 |
| Human Interact | 真实请求、回复、已确认指导、主动材料及处理和研究影响。 |

选择本次相关的入口，共用同一份 RM 精确内容；视角增加时补充含义与关系。无文件对象可以直接登记研究含义，数字内容按需要保管。六入口的发现与复用见 [研究导航](research-navigation.md)。

### 共同整理原则

**保留来路，开放用途。** 复用已有对象、内容和精确版本，记录实际新增的处理、派生与用途。处理者、接收者和真实生产者分别按事实说明；相同内容可以共用，不同工作的实际生产记录保持可区分。

**沿职责确认正式状态。** Agent 作出研究选择，工具协调 RM 内容、RG 关系与真实 HC 协作来源。正式对象、版本和结果沿本次角色获授能力提交并接纳，工作材料保留其暂存或未接纳状态。普通登记不替代建题、结果接纳或人的确认。

**以能够接续作为整理的尺度。** 后继应能从相关入口找到记录，理解来源、用途和必要限制，并沿准确入口取得所需内容。无保留价值时可不登记；值得保留但尚未完成的部分，说明现状、依赖与接续安排。

### Stage 自产材料、正式阶段正文与独立保管归属

Idea、Plan、Bundle 和 Reasoning 可在本阶段调查、推导和综合，工作材料、脚本和图像可暂存 Workspace，阶段认识写入 notes。阶段判断与论证沿本阶段既有正式输出和接纳路径交接；已由正式阶段正文承载的论证沿该正文既有身份交接和读取，无须普遍另行登记为资产或包装成 Target；正文可读或具有 `StageCommit` 不自动增加 `selected_evidence_bindings` 的来源类型，独立正式采用仍沿既定五类来源与 Owner 映射。选定需独立长期保存或作为正式依据交接的数字材料，再按上表 `managed`／`linked_local` 方式沿获授材料入口取得准确版本与 reader，无须先将每份草稿或临时笔记入库。

正式整理时保留实际生产来路：调用 intake 的根只确定本次提交绑定，不自动证明实际接收者或生产者。执行或接纳绑定已能核验的工作身份及研究关联，由相应 Owner/adapter 沿既有事实给出；尚不能核验的关联如实保留为来源说明，不升级成系统已核事实；角色如实说明科研内容、真实生产与接收来路、处理派生、用途及限制。后继沿该 Question 的阶段产物或资产研究关系取得正式身份与准确 reader。阶段正文沿已经交付的准确交接与 reader 使用；独立 Stage 资产生产关系及按 Question 的完整发现以实际提供的能力为准，当前 `query_question_research_notes` 只查 Target notes。

已获授权的非 Target 文件、二进制和目录可直接通过 `research_memory.assets.intake` 选择：`source_kind:"local_path"`（文件或目录）或 `"directory"`，`custody_mode:"managed"` 或 `"linked_local"`，并提供 `display_name`。工作区来源为 `source:{kind:"workspace",workspace_ref,path}`；原始材料来源为 `source:{kind:"material",reference_ref,path}`，其中 path 为安全相对路径，材料引用的空路径表示所选原件。仅所选内容进入保管，不因登记而扫描、复制全部工作区；二进制无须转成 UTF-8。原有 `text` 与 `target_workspace_note` 分支保持，Target 笔记继续使用其专门来源核验。返回的 `AssetIntakeResult.reader` 指向准确版本，按其中 operation 调用，不能把 intake 成功当作原件永远可用。重复提交与未知结果对账使用同一 effect_id 和相同参数；`.intake.reconcile` 在当前对账权限内，可于原件已离线或原根因求助而暂停时返回原接纳或失败结果，实际正文可用性仍由 reader 当次核验。工具记录来源工作或原接收关系，调用方额外 provenance 仅保留为 `declared_provenance`，不视为已核验生产关系。

### Target 过程中积累的资源

Target 沿 [正式工作交接](../target-execution/references/formal-work.md) 提交实际执行、产物和适用评价。正式接纳后由 Bundle 整理可复用资源；Bundle 已不再运行时，由 Reasoning 在综合交接前承接。沿准确 TargetCommit 和正式结果入口读取资源候选，关联真实生产工作与精确内容，根据用途补充 Dataset、Environment、Literature 等身份、版本、派生和关系。

Target 过程中发现、取得或阅读的 Literature 也进入整理范围。外部文献保留作者、出版或获取来源及准确原文入口；本次阅读、分析、支持或反对的主张、限制与采用背景关联实际 Question／Target 工作。已接纳文献沿原有引用复用，新材料按实际来源和保管状态登记或关联；尚未取得全文时如实保留线索及读取状态。复制论文或撰写阅读笔记不把外部论文变成本 Target 的原创产物，也不单凭提及文献声称已经阅读或作为执行输入采用。

已有实施与评价保持正式身份，整理用途无需重新制造执行。Agent 可以委派具体整理，根核实实际采纳的关键内容及登记结果。本次选定且当前可登记的积累已有可读内容与必要关系，未决部分已有真实交接时，完成本次整理。

### 目标演化后的重新理解

方向改变后，重新判断已有积累的适用性和用途。过去的工作是在当时目标与条件下开展的，其完成事实、取得的证据和正式内容保持真实历史；仍有价值的部分继续复用。新的用途与判断沿关系补充，让后继能够同时理解当时的依据和现在的选择。

## 交接与工作区收尾

各阶段及具体工作使用自己的 Workspace，按 Quest 的正式研究序列统筹生命周期。近期窗口保留当前 Cycle 与前两轮；最初不足三轮时保留实际轮数，同一 Session 的技术重试、turn/job 变化或恢复不增加轮数。每轮可有多个阶段与 Target 目录；本根实际可读范围按[当前工作目录](#当前工作目录与回复材料)中的宿主路径提示确定，无须复制、重排工作台或预先枚举全部文件与 hash。

Cycle Workspace 退出三轮窗口后由系统清理：只在原位保留 RM 正式以 `linked_local` 保管的资产原件（文件或目录）及必要父目录，其余文件与目录删除；没有这类原件时整目录删除。语义退役或原件暂时离线不解除其保管位置保护。保留原件不扩大工作路径的可见范围，窗口外正式原件仍沿 RM 准确 reader 读取。

活动、恢复、读取、待接纳或完成状态不增加窗口外 Workspace 的保留条件。需要跨窗口接续的材料应及时沿正式保管路径保存。系统核对工作目录的安全路径边界并执行删除，Agent 无需遍历或代为清理；人提供的只读原目录不属于临时清理对象。

原生 Session 的退役与回收沿其既有运行生命周期处理，与上述 Workspace 清理条件分开。正式研究内容、准确输入、必要操作结果与公开历史保持各自保管关系，不复制全部对话另建台账。Companion、Acquisition、Recorder 等非 Cycle 根的持久工作沿自身生命周期。

长期积累通过研究检索、关系追溯、正式内容读取和登记能力接续；具体操作由本次提供的 MCP 工具组与准确入口承担。独立助手的持久 Workspace 和可靠外部原件按各自生命周期处理；Writing 的材料与产物沿调用方原任务的保管与生命周期安排。

## 工作资料的当前处理与后继交接

HumanRequest 答复的绑定与恢复接续见[当前工作目录与回复材料](#当前工作目录与回复材料)；软指导附带材料、主动意见与新闻论文先交给提交时绑定的当前研究根。Agent 自行取得的服务器材料用 `research_workspace.materials.acquire` 提交 `absolute_path` 由系统安全检查生成引用，或提交既有原样 ServerSelection，并说明真实取得路线；材料绑定本根，不按后来前台改投。三种来源均先作为工作资料；保存引用、收到、实际读过、采用与足以支持科研结论是不同事实。新闻、人的判断、论文及实际实验产物保留各自性质。

先用 `research_workspace.materials.discover` 发现可见 reference_ref，按需要展开目录，再以 observation_ref 调 `research_workspace.materials.read`，沿字节范围继续。未读、只读局部、缺失或权限失败均如实说明。需要修改或轻量试跑时，用共同 `research_workspace.materials.copy` 按需取得单个独立可写副本；返回的 working_path 可用本根原生工具处理，重试用同一 effect_id 或 `.copy.reconcile`，不会覆盖已编辑副本。运行根副本在 `.work-materials/`，临时结果也可放此处；不要把未选材料移入 Target 的常规 outputs 目录。原件保持完整，不递归复制或预读整个目录。

由接收根先完成当前可做的初读、判断和处理，用 `research_workspace.materials.feedback` 声明 understanding、disposition（adopted／considered／deferred／not_used）、changes、continuing_work、reasons 和 limitations。采用必须有该根实际读取记录；反馈仍是根的声明，不是科学支持、目标完成或独立核验证明。说明对当前安排或判断的实际影响、依据与未采用理由，保留未读范围和未决事项。可分次补充，以不同稳定 effect_id 表达真实后续处理；未知结果先 `.feedback.reconcile`。

selections 按研究价值选择原件、处理结果、两者或 `[]` 均不保管。每项写实际 purpose 和 managed／linked_local custody：原件 source 为 `{kind:"original_file",path,observation_ref}`；处理结果按宿主提供的工作目录定位文件，核对其 SHA-256 后填写 `{kind:"workspace_file",workspace_ref,path,expected_sha256}`。选中项沿既有 RM 内容接纳及 RG source-material 用途关系保存，返回 asset_binding、role_ref 和精确 reader。linked_local 留在实际位置，后续来源变化如实报告漂移；未选副本与输出不会因反馈或 Target 收尾自动入库。真实 Target 实施、评价和产物仍沿正式结果交接，不由材料反馈虚构 Run、MetricResult、Evidence、Dataset 或 Environment。

后继根在本 Quest 的 `materials.discover.retained_treatments` 检索真正选中的内容、原始 receiver、实际处理根、用途与影响，沿 next_offset 分页，再把 selection.reader 交给 `research_memory.content.read` 精确读回；原投递不重新绑定。材料较多时可委派聚焦工作，根负责当前初读、影响判断及必要交接。需重做上游或下一轮投入时，由现有交接经 Reasoning 安排后继 Cycle；不因收到材料强制新建 Cycle，也不在同轮回退阶段。

正式指导附带材料及其 retained_treatments 保留 source_guidance 的原文、助手理解、确认范围、力度和保留条件。交接后继续保留该边界；材料可供后继读取研究背景，不能把只适用原 Cycle 或 Target 的要求扩大到后继工作。材料本身可按研究价值独立采用和验证，既有科学接纳合同不变；scope_confirmation=legacy_unconfirmed 的历史来源如实保留未记录范围确认的事实。

人提交的服务器工作资料引用用 research_workspace.materials.discover 按页发现当前根可见的 reference_ref；指定引用和安全相对 path 时只展开一层目录，再用 research_workspace.materials.read 携带 observation_ref、offset、max_bytes 按需要读取最多65536字节。返回实际服务器、来源、接收 root/work、可用性和成功字节范围，UTF-8 或 base64 正文沿 next_offset 继续。delivery.work_materials 中的 reference_ref 使用同一 reader，仍属于原 HumanRequest 的工作；不随前台切换或后续 Cycle 改绑。无需 RM binding 即可发现和读取，大原件不要求先复制、递归预读或全量 hash。保存、可用、未读、成功读取与理解分别判断，失败和未展开部分保持如实记录；理解后是否正式采用仍沿既有 Owner 接纳流程。

具体方法、实施与评价按阶段 Skill 和正式合同记录，产物按真实来源和用途交接。已授权的获取、处理和大型产物保存自主完成；文件达到多 GB 本身不构成请人导入的理由。需要新增外部权限、受限访问、额外资源或人类亲自行动时，再用 human_request 请求缺少的具体条件。

## 准确读取与错误

收到 summary_only=true 的 stage-context-presentation 时，将其视为导航摘要，完整 Owner 冻结输入保持原状。目录提供 research_memory.stage_context.read 时，必填 context_pack_ref、source、path、offset、limit；path 为 JSON key 字符串数组，数字字符串表示数组索引，[] 读取整个来源；offset/limit 是 UTF-8 字节，limit 为 1..16384。source 可选 context_pack、question、literature_records，或用 scientific_outcome/predecessor_closure 加 source_ref 读取精确 outcome/commit 原文。question_history、question_index、evidence_index 提供目录；先沿 byte next_offset 读完本页 JSON，再按 index_page.next_offset 设置 index_offset 翻目录页，同时将 byte offset 归零。核对来源 ref/hash，只展开当前判断需要的部分。阶段冻结上下文与正式采用保持原 Owner 绑定；共用正文 reader 可用于同 Quest 的普通参考阅读，Plan 选择后仍由原接纳路径核验。

准确 reader 每次核对当前授权、范围和接纳身份。相同不可变来源、所选路径及表示可复用已编码字节及该表示自己的摘要；current history/index 没有准确修订身份时每次重新读取。可变文件每次打开都核对实际字节，校验与取页共用同一次读取；stat 未变化不能证明内容相等，也不能以 context_pack_hash 代替正文 content_hash。原件缺失或漂移分别按 reader 的准确错误处理；本次已验证的值直接交给消费者，另一次打开仍重新核验。

常规资产页只附所选版本的当前／被替换／退役状态、适用说明及 history_reader；详细变更沿该入口按需读取。资产语义状态不代替实际原件可用性，历史精确引用保留原义。

reader 指针只把 operation 以外的参数交给指定工具；summary_only 是外层展示标志，不是 research_notes_reader 的调用参数。序列化 JSON 的 offset/limit 按 UTF-8 字节计，以 next_offset=null 结束；complete 仅说明单页是否包含全部来源，尾页仍可能为 false。资产文件页按字节计，以 complete=true 结束；目录页按 entries 计，以 next_offset=null 结束。不要混用这三种结束条件。

公共 MCP 工具错误按 isError 和 code 判断；文本 JSON 与 structuredContent 保留同一 details。参数错误按 path、requirement、expected 修改自己的字段或材料；正常 Owner status 仍表达业务状态。capability_unavailable 表示操作未注册、未获 grant 或依赖当前不可用；content_version_unbound 表示本次 source/version 在授权范围内未绑定，应核对精确引用或重新发现适用版本，不能据此断言全库不存在。授权不足、宿主漏参、损坏合同和服务故障按实际原因交给相应负责方处理，不修改工具、校验规则或科研事实来绕过拒绝。

失败若未确定原效果，先保留原提交及 operation/effect 身份，沿返回的 reconciliation_operation_id 和该操作合同对账；部分对账需要原完整提交，不能只传 effect_id。接纳结果继续复用，不重跑有效工作；未知时既不更改原提交盲重试，也不换身份重复写入。输入校验只证明本次调用未执行 handler，不证明更早的操作未生效。

## 当前工作目录与回复材料

同一 TargetRun 恢复时，原工作目录仍保留且获授可达的，沿用原 `workspace_ref`、物理目录与工作字节，按已保存 checkpoint 继续；执行身份和工具权限由宿主重新签发、核验。旧路径与旧授权不能替代现任权限，已冻结输入、准确版本及 Owner 接纳仍沿原合同处理。

宿主在本次输入的 `Work directories` 中列出实际可达且属于本根范围的工作目录；每项的 `directory` 是原生文件／shell 的入口，`workspace_ref`、`work_ref`、`root_kind`、`cycle_ref` 及适用的 `target_ref` 说明工作归属，`access` 说明读写范围。只在自己的 `read_write` 目录内编辑工作文件，`read` 目录用于只读参考；Target 的正式 inputs 等受保护内容仍按原合同使用。原生执行沿实例已有 Harness 权限，路径提示不扩大权限；父目录、私有 spool、内部数据库及越出获授范围的符号链接不在授权内。普通目录查找和读取直接用原生能力，无须经过专用 RW 工具或工具索引。

Cycle 根的路径来自同一 Quest 当前及前两轮窗口，并按本根实际工作筛选：本轮列出自己的工作目录及已存在的上游阶段目录；Bundle／Reasoning 还可见本轮已启用 Target 的目录，Target 可见本 Target 的工作目录历史。窗口内较早轮次的可见阶段与 Target 目录可供参考。晚到的旧根仍受当前窗口与自身工作限制，不因恢复而取得更新轮次或重新开放完整第四轮。Companion、Acquisition 等不属于 Cycle 的工作只按自身获授范围访问，不套用三轮目录承诺。

缺失、不可读或不在本根范围的目录不出现在路径提示中。未列出不等于没有历史、材料已删除或已被读完，也不能从相邻路径推断权限；需要相关内容时沿已有准确引用或 RG／RM 等正式 reader 核实，仍不可达则说明具体缺口。路径已经给出而读取失败时，保留实际失败与未读范围。目录可达不表示内容已被正式接纳；窗口外原件和研究历史沿准确 reader 读取，回收边界见[交接与工作区收尾](#交接与工作区收尾)。

正式回复的 delivery 绑定原 HumanRequest、根 Session、work 与可选 Cycle。同一 TargetRun 恢复后的现任根可处理合法历史根的答复，保留原 request/root/work/delivery 与去重身份；其他 TargetRun 的根不能承接该投递。原根用原 effect_id 调用 human_request.open.reconcile 后，按 resolution.response_ref 调用 human_request.read；恢复后的现任根沿原 request_ref 与 response_ref 读取，保留原接收关系。delivery.reply_file 与 uploaded_files 给出 workspace_ref、相对 path 与 sha256，在该工作实际目录用原生工具读取 reply.json 和需要的上传文件；核对字节后再作为准确依据。linked_locators 保留所选原件的位置说明；其目录或文件也进入 delivery.work_materials 的既有授权材料引用，按当前授权及实际可用性读取，先展开必要条目，不复制全目录。library_reconnect 的 provided_material 路线也先读工作文件再继续原工作；OA 路线与恢复机构访问仍按实际路线处理。提交回应不自动登记 Literature、Dataset、Environment 或 ResearchAsset；Agent 判断有复用价值时，再沿既有 RM／RG 接纳与登记流程处理。Target 的 implementation、inputs 和 outputs 按原正式交接合同使用。

宿主使用同一研究序列窗口判定目录可见和回收时机；目录删除及正式原件保留按[交接与工作区收尾](#交接与工作区收尾)处理。

主动指导可随 work_materials 上传小文件（uploads），与所选外部目录分开处理。上传文件投递到已确认 receiver 的实际工作空间，回执 uploads 保留接收 work/root、相对路径及 SHA-256；二进制无需转换为文本。外部原目录保持只读原位引用。投递失败或结果未知保留原提交身份重试；pending 投递不表示正式指导已接纳，也不自动生成正式资产或生产关联。
