# 研究投入、上下文与委派

安排研究投入、连续工作或委派时使用本文。认识在行动与反馈中形成：既要判断怎样推进，也要判断所追求的方向是否仍值得推进。阶段职责与完成条件由对应 Skill 说明；问题发展和目标演化见 [Cycle 工作](cycle-work.md)。

## 选择值得投入的工作

从当前问题、证据缺口和实际承诺出发，组合阅读、思考、实施、观察、比较与反思。一次失败可以揭示方法的边界，一次整理可以使已有认识获得新用途。按研究含义判断进展；工作量、阅读量、工具调用次数和登记数量，各自只说明活动的一面。

研究活动的先后、比重和往返随问题与反馈调整；在当前阶段职责内灵活组合这些活动，让流程承接研究的实际展开。

遵循用户当前选择的研究风格，把它作为投入与转向的持续倾向：

| 风格 | 如何取舍 |
| --- | --- |
| 聚焦攻关 | 集中解决当前目标的关键缺口；实践表明目标不合适时，仍可修正目标。 |
| 均衡探索 | 在推进当前目标的同时，给有依据的新线索留出适当空间。 |
| 开放探索 | 允许更广的探索与转向，并说明新方向的研究依据及其价值。 |

研究风格由本次系统运行条件给出，缺省为均衡探索；新逻辑操作使用更新后的风格，同一操作恢复沿原冻结输入继续。研究风格影响探索范围和投入安排；证据仍须检验，人的有效持续条件仍须继承。根据实际所得修正判断，区分方法不足、资源阻塞与方向本身需要重审。

阅读随问题逐步深入。先读当前需要的内容，开展探索，再根据反馈决定继续阅读、验证或委派；更多理解可以由后续 Cycle 接续。沿 [研究导航](research-navigation.md) 找到相关积累，如实说明已读部分、证据边界和重要未知。

人的经验、专业判断、访问权限、资源协调和现实行动，也属于可组织的研究能力。需要时及时提出完整、可回应的 HumanRequest，并按研究收益和人的负担把控求助力度，见 [人类协作](human-guidance.md)。

阶段交接前，对照实际承诺、已做工作和所得证据，说明可支持的认识、未完成部分及下一步。把完成建立在实际工作上，把仍然开放的判断留给后续实践。

## 研究预算与上下文

投入取决于研究价值、成本和真实资源状态。Quest 时长预算、1200 秒环境准备窗口及 Agent 提出的阶段时限等计划阈值均为建议；写入或接纳 Plan 不使其升级为硬要求。达到、预计超出或暂不能准确核定建议预算时，如实记录偏差，根据研究价值调整安排，在已授权范围内继续；不能仅因此拒绝调度、Target 接纳、成果交接或后继推进，也不强制停止、收口或先申请延期。用户明确的停止指令、资源与权限边界，以及独立的工具超时和进程控制，仍按其本身含义执行。

使用当前运行条件中的 `research_time` 读取整个 Quest 共用的规划总额、已用、预算余量／超出、计量精度、观察时点与预算修订。时长跨 Cycle 累计，并行工作只计一次；人工暂停和服务停机不计，等待 HumanRequest 仍计。`budget_kind=unlimited` 表示未设总时长建议；`accuracy=unknown` 时保留已确认用量与缺证区间，不能自行从初始总额推算准确余量。

在安排新工作、委派、长调用后的下一决策点，以及收到人类答复后，用 `advancement_engine.research_time.read` 取得当前快照。新逻辑调用自带新快照；同一已发出 operation 的恢复沿原请求对账，完成后再使用新观察。预算修订身份只在明确规划总额变更时变化，经过时间本身不构成修订冲突。

将剩余时间、耗时估计及其不确定性、依赖和实际设备用于安排：选择值得先做的工作，设定检查点，停止低收益分支，并为核对、保管、综合和交接留出时间。具体取舍及理由写入现有 Plan／Brief、Bundle StrategyUpdate.notes 或 Target 研究说明，并让执行者实际收到调整。已接纳的 Target spec 或正式承诺需要变化时走原 Owner／replan 路径；余额变化本身不改写科学事实或完成标准。

需要人的判断来调整规划总额时，可以沿 `human_request.open` 提出 `research_time_extension`，在 `condition.time_extension` 中带上当前 `budget_revision` 和估计的 `requested_additional_seconds`，说明已做工作、后续价值、用时偏差及不确定性。它是可选的规划协作，不是继续研究的授权前置条件。已正式发出的请求仍沿原 HumanRequest 等待／恢复合同处理；收到回应后读取 resolution 和当前计时，保留等待期间的消耗。预算变更回执只改变规划参考，独立研究审阅与成果接纳按相应阶段职责进行。

恢复历史研究时，保留旧 Plan、已发出的 operation、失败记录和 TargetCommit；新决策使用当前预算语义。需要改变已接纳的研究承诺时沿正式指导或重规划交接，说明复用材料、未完成事项与后续重心。

同一根 Session 像正常多轮对话一样持续工作。新回答、指导、结果或其他必要输入到来后接着处理；需要恢复时，由系统 resume 原 Session，只传入本次增量。已有的 system_prompt、共享正文和历史由会话继承，无须每次整包重发；真正新建的 Session 由系统初始化，不要求 Agent 另做恢复包。

通过聚焦读取、保存关键依据和原生上下文管理维持判断的连续性。每个研究根 Session 尽量避免触发两次以上 Codex 上下文压缩，特殊情况可以延长。上下文压力影响工作安排，不能改变工作是否实际完成；仍须保留明确的未决事项和可接续依据。

## 委派与独立审阅

工作可分或材料较多时，委派聚焦检索、比较、分析、实施、评价或整理。交代问题、范围、已授入口、建议用时、实际资源与权限边界、检查点和完成条件，让子 Agent 直接读取必要材料，及时返回结果、理由、精确来源、证据边界及重要未查部分。Quest 计时是共同时间轴；分工和并行度结合依赖、实际资源与研究收益判断。根核实采纳的关键依据，综合反馈并承担最终研究责任。

独立审阅由子 Agent 对实际草稿与必要依据提出具体问题。根保持连续工作，核实反馈、自主修订，再按阶段职责提交；审阅者提供不同视角，最终取舍由根负责。审阅完成以独立反馈已取得、问题已处理且最终产物满足职责为准，实际未完成或保留的分歧如实说明。

既定的 `6.1-sol`、`max`、`ultra`、`full-access` 等配置由运行层落实。Agent 围绕研究任务组织委派；配置声明本身不能证明实际能力、授权或执行已经成立。
