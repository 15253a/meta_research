# 研究投入、上下文与委派

安排研究投入、连续工作或委派时使用本文。认识在行动与反馈中形成：既要判断怎样推进，也要判断所追求的方向是否仍值得推进。阶段职责与完成条件由对应 Skill 说明；问题发展和目标演化见 [Cycle 工作](cycle-work.md)。

## 选择值得投入的工作

从当前问题、证据缺口和实际承诺出发，组合阅读、思考、实施、观察、比较与反思。一次失败可以揭示方法的边界，一次整理可以使已有认识获得新用途。按研究含义判断进展；工作量、阅读量、工具调用次数和登记数量，各自只说明活动的一面。

研究活动的先后、比重和往返随问题与反馈调整；在当前阶段职责内灵活组合这些活动，让流程承接研究的实际展开。

遵循用户当前选择的研究风格，把它作为投入与转向的持续倾向：

| 风格 | 如何取舍 |
| --- | --- |
| 聚焦攻关 | 集中解决当前目标的关键缺口；实践表明目标不合适时，仍可修正目标。 |
| 均衡探索 | 在推进当前目标的同时，给有依据的新线索留出适当空间。 |
| 开放探索 | 允许更广的探索与转向，并说明新方向的研究依据及其价值。 |

研究风格由本次系统运行条件给出，缺省为均衡探索；新逻辑操作使用更新后的风格，同一操作恢复沿原冻结输入继续。研究风格影响探索范围和投入安排；证据仍须检验，人的有效持续条件仍须继承。根据实际所得修正判断，区分方法不足、资源阻塞与方向本身需要重审。

阅读随问题逐步深入。先读当前需要的内容，开展探索，再根据反馈决定继续阅读、验证或委派；更多理解可以由后续 Cycle 接续。沿 [研究导航](research-navigation.md) 找到相关积累，如实说明已读部分、证据边界和重要未知。

人的经验、专业判断、访问权限、资源协调和现实行动，也属于可组织的研究能力。需要时及时提出完整、可回应的 HumanRequest，并按研究收益和人的负担把控求助力度，见 [人类协作](human-guidance.md)。

阶段交接前，对照实际承诺、已做工作和所得证据，说明可支持的认识、未完成部分及下一步。把完成建立在实际工作上，把仍然开放的判断留给后续实践。

## 研究预算与上下文

投入取决于研究价值、成本和真实资源状态。Quest 研究时长预算跨 Cycle 累计；使用系统提供的已用、剩余、设备和资源信息，按实际运行口径理解暂停、等待与并行计时。静态上限不能说明当前剩余，未知信息保持为未知。

同一根 Session 像正常多轮对话一样持续工作。新回答、指导、结果或其他必要输入到来后接着处理；需要恢复时，由系统 resume 原 Session，只传入本次增量。已有的 system_prompt、共享正文和历史由会话继承，无须每次整包重发；真正新建的 Session 由系统初始化，不要求 Agent 另做恢复包。

通过聚焦读取、保存关键依据和原生上下文管理维持判断的连续性。每个研究根 Session 尽量避免触发两次以上 Codex 上下文压缩，特殊情况可以延长。上下文压力影响工作安排，不能改变工作是否实际完成；仍须保留明确的未决事项和可接续依据。

## 委派与独立审阅

工作可分或材料较多时，委派聚焦检索、比较、分析、实施、评价或整理。交代问题、范围、已授入口和完成条件，让子 Agent 直接读取必要材料，返回结果、理由、精确来源、证据边界及重要未查部分。根核实采纳的关键依据，综合反馈并承担最终研究责任。

独立审阅由子 Agent 对实际草稿与必要依据提出具体问题。根保持连续工作，核实反馈、自主修订，再按阶段职责提交；审阅者提供不同视角，最终取舍由根负责。审阅完成以独立反馈已取得、问题已处理且最终产物满足职责为准，实际未完成或保留的分歧如实说明。

既定的 `6.1-sol`、`max`、`ultra`、`full-access` 等配置由运行层落实。Agent 围绕研究任务组织委派；配置声明本身不能证明实际能力、授权或执行已经成立。
