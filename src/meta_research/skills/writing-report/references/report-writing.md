# 研究报告写作

在本次助手或研究任务中按主 Skill 写作原则处理报告；局部写作使用相关指导，完整成品使用下列交付要求。报告以读者能准确理解“为什么做、如何做、得到了什么”为中心。

## 组织方法与结果

先确定受众、用途、所选研究范围、报告类型和用户模板。进展报告、技术报告、实验报告和决策报告需要不同深度；结构与标题服从用途和模板，不固定套用论文贡献叙事。

通常交代目的与范围、研究对象/数据、条件和方法、实际执行、结果、解释与结论。方法应足以理解结果怎样产生；结果区分真实观察、计算值和解释。必要的参数、数据分割、评价协议、样本、单位、排除或缺测要可追溯。

按科学问题或工作包组织可阅读的说明，关键时间顺序仅在影响方法、数据或结果时出现。实验记录可作为依据或附录，报告正文不复制工具流水、Agent 对话、Cycle 调度和审核处置。研究相关失败、未完成项和负面结果按其对结论的影响说明。

## 语言、表格与结论

采用直接、严谨、具体的叙述，清楚区分计划与实际完成。对比表、结果图和必要方法示意应有明确标题、单位、样本和来源。相关计算真实执行，依 [科学表达与证据](scientific-writing.md) 保留输入和方法。

结论回答报告目的，交代可支持的判断及必要适用条件。人类独立交付发现的额外实验建议按 [操作边界](context-and-handoff.md#完成责任与操作边界) 单独交给人。报告不要求制造创新或强故事；也不把严谨理解为逐段贴置信标签或反复免责。

配套 PPT 以真实、准确说明为主，保留目的、条件、方法、实际结果与适用范围，按 [演示指导](presentation-v1-advisory.md) 组织为清楚的视觉讲述。

## 模板与交付

读取用户 DOCX、LaTeX 或其他报告模板，保留标题层级、页眉页脚、编号、图表和书目样式。模板样例不属于研究事实。没有模板及其他要求时，默认采用便于查阅的 DOCX 排版并附 PDF；这是一项可被用户要求覆盖的制作选择。

按要求交 PDF、DOCX 等正式文件及适当可编辑源；Markdown 可以是中间源或用户明确要求的成品。实际渲染并检查目录、分页、表格跨页、图注、引用、字体和可读性。源文件与最终文件必须对应审阅后的同一内容。

完成条件：方法、结果与结论足以让目标读者准确理解；实际执行与未完成项无混淆，数字和来源可核对；模板正确、文件可打开并已完成视觉检查。
