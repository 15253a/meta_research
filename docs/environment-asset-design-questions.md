# Environment 与六大研究入口设计

日期：2026-09-24。状态：Q1 已选 A，Q2 已确认现成环境可直接登记；用户进一步纳入已有设备和现实物理资源，并明确六入口分别侧重进展总览、过程方法积累、产物与资源复用。保留 Baseline 执行与存储层级，Target 新产物的 Environment 与 Dataset 共用入库整理时机，其他机器的适配或修复由新 Target 处理；本文不代表实现或部署。

## 用户提出的方向

在现有五个研究入口之外增加环境入口。用户指出 Baseline 表达方法，Dataset 表达数据；可复用运行环境、Simulator 是值得全局积累和复用的重要资产。

第二轮用户进一步明确：Baseline 按目前的执行逻辑存储没有问题，Target 仍按 Baseline 层级检索、构建并存储成果。Dataset、Literature、人类输入及 Environment 是便于直接索引的入口，用户用“快照”描述这一作用；尤其数据集和环境可能构建昂贵、长期常用，环境也可能是 Target 的产物。Environment 与 Dataset 同时入库核验最方便。

第三轮用户确认 Q2：现成环境可以直接登记。其他机器上无法使用时，修复是新 Target 的事，与原模拟器的入库资格无关。

第四轮用户扩展 Environment：实验者已有资源、设备以及真实物理世界中可复用的东西也应纳入。六入口中，Baseline／Target 与 HumanRequest 侧重过程和方法复用，Literature、Dataset、Environment 侧重重要产物或资源复用，Question 提供类似研究进度报表的总览。

## 既有定义与约束

- [CONTEXT.md](../CONTEXT.md) 将 Baseline 定义为研究方法及其适用条件；具体实现、输入和实施产物由 VariantRun 关联。方法入口可以展开这些关系，不意味着方法定义与某次运行结果是同一对象。
- 先前五个研究入口是 Question、Baseline、Dataset、Literature、人类输入；本轮加入 Environment 为六入口。它们与 RG、RM、AE、AR、HC 五个后端模块属于不同层面的概念。参见 [ADR 0005](adr/0005-research-assets-and-shared-content.md) 和本轮 [ADR 0006](adr/0006-environment-as-reusable-research-index.md)。
- 既定原则是 RG 组织研究含义和关系，RM 保存实际内容与精确版本；同一原件可被不同研究角色引用而不复制。具体归类及复用粒度由 Agent 按研究含义判断，不为每种场景新增分类硬规则。
- 现有“运行条件”表达当前 Quest 本次选择的 GPU、时间预算等工作条件，参见[运行条件实现说明](../../../runtime-conditions-8768-20260924/实现与验收.md)。已有 GPU／算力设备本身可由 Environment 索引，两者分别表达资源和本轮对资源的使用安排。

## 当前入库事实

当前 Target 通过 `dataset_candidates` 声明候选数据产物，finalizer 按所声明边界保存精确 RM 资产；正式接纳后，Bundle 判断复用价值并登记 Dataset 身份、版本及研究用途。最后一个 Target 后若没有后续 Bundle，则由 Reasoning 在自己的综合交接前承接整理。参见 [Bundle skill](../src/meta_research/skills/bundle_stage/SKILL.md)、[Reasoning skill](../src/meta_research/skills/reasoning_stage/SKILL.md) 和 [Dataset 使用说明](dataset-lineage.md)。

Dataset 接纳核验资产身份、版本、内容 hash、receipt、当前写入范围及研究引用等；是否具有复用价值由 Agent 判断，接纳不自动证明科学正确性。Environment 尚无对应专属索引能力，本轮决定让它加入同一入库整理环节，不宣称该能力已存在，也不把“同一环节”改写为 Target completion 内已有自动全量登记。

## 已确认范围与定位

Q1 已选 A，并按后续补充扩大：Environment（研究环境与资源）作为第六个研究入口，覆盖可跨研究采用的运行或交互条件及现实资源。Simulator、计算运行环境、实验者已有设备、设施、场地和其他研究用途的物理资源均可纳入。既有 Agent 自主判断复用意义和登记粒度的原则保留。

Baseline 体系保留构建、实施及其成果的既有组织方式；Environment 增加从“可复用环境与资源”出发的直接发现和采用入口。Target 新产生的环境索引关联实际内容及生产或获取来源，与 Dataset 一同进行完成后的入库整理和核验。已有设备设施和现实资源按真实来源直接登记，不要求先由 Target 构建。这里的“相同时刻”落在共用工作环节上，不自行推导为新的批量原子事务或审批流程。

“索引快照”在本次讨论中可理解为对象含义、用途、来源和所指资源的概览与引用。数字材料指向实际采用的内容版本；实体资源通过身份、位置、能力和已知条件等资料被识别，相关说明和使用记录可保存在 RM。对说明文件做内容 hash 不等于冻结或核验设备本身。索引不要求复制原件，也不意味着可以丢掉语义身份和用途记录后仅从文件重新生成。Literature 可由外部获取，人类输入保留请求、回复和主动指导等真实来源，不要求所有索引对象都先被包装成 Target 产物。

六入口的侧重点见 [ADR 0006 的对应表](adr/0006-environment-as-reusable-research-index.md)：Question 组织问题与研究进展，Baseline 和 HumanRequest 组织方法与协作过程积累，Literature、Dataset、Environment 提供重要产物和资源的直接复用。入口可以交叉关联，同一设备的获取与调试经过可以在过程入口找到，而设备本身从 Environment 找到；Question 汇集采用该设备的研究进展，不替代研究问题本身。

以下例子用于解释已确认范围，不固化类型枚举或数据库层级：

| 概念 | 含义说明 | 示例 |
| --- | --- | --- |
| 研究交互或仿真环境 | 方法可在其中观察、操作或模拟的研究条件与规则 | 交通仿真环境、机器人任务环境、用于 Agent 实验的可重置网站 |
| 计算运行环境 | 可再次建立或使用的一组软件运行条件 | 经整理可复用的 Python/CUDA 依赖环境、容器镜像及使用说明 |
| 现实研究资源 | 已有或外部提供、可供研究采用的实体资源 | EEG 采集设备、GPU 服务器、实验台、实验室设施、野外观测场地 |
| 环境实例 | 一次实际使用时的进程、状态或会话 | 某次启动的模拟器进程及本次随机种子、临时工作目录 |

例：在同一交通模拟环境中比较方法 A 和 B，A/B 对应方法资产，模拟环境可有自身资产身份，既有交通记录可作为 Dataset。该环境生成并保存、值得独立复用的轨迹也可以登记 Dataset，关联真实生成工作并共用内容。若研究本身提出新模拟算法，该算法的方法角色与其可复用环境角色可以关联，不强迫二选一。

Environment 的身份与版本不应自动等同于某次启动实例。现成环境可以按已有持久目录、安装状态或可访问服务及其使用说明直接登记，完整打包、完整重建配方和跨机器可移植性不作为统一入库门槛。

例如，实验者告知实验室已有一台 EEG 采集设备：该人类输入保留其陈述及背景，设备可直接进入 Environment 索引并关联说明。后续 Target 采用设备按 Baseline 方法采集，数据进入 Dataset，调试和采集实施仍保留在原方法层级中；Question 入口汇集本次研究工作与进展。设备无需先被包装成构建任务，也无需被表示为可复制的软件包。

例如，Target T1 在机器 A 上构建并保存模拟器 S，S 可以进入 Environment 索引。后续研究在机器 B 上采用 S 时发现依赖不兼容，由新 Target T2 处理适配或修复，T2 沿原 Baseline 层级保留工作和结果并关联 S；这不推翻 T1 的构建成果，也不要求原模拟器先适配 B 才能入库。实际内容有变化时沿已有精确版本原则保存，是否形成新的索引身份或版本由 Agent 按研究含义判断，不新增分类硬规则。

## 设计树与已确认决定

- 已定 Q1：A，覆盖研究交互／仿真环境与可复用计算运行环境；后续明确加入实验者已有设备、设施及现实物理资源。
- 已定 Q2：允许现成环境直接登记，跨机器适配或修复属于新 Target，不成为原环境入库的前提。
- 用户主动明确：Baseline 执行／存储层级不变，Environment 提供直接复用索引；资源可以已有，也可由 Target 构建；Target 新产物与 Dataset 共用完成后的入库整理和核验时机。
- 六入口侧重点已明确：Question 为问题与进展总览，Baseline／Target 和 HumanRequest 为过程方法积累，Literature、Dataset、Environment 为重要产物与资源复用；各入口保持关联，不作互斥分类。
- 不重新提问：具体归类交给 Agent、同一内容共用引用、第一版不提前发布未完成 Target 产物、无需为环境增加一套批准流程。

本轮关于 Environment 是否新增、覆盖哪些对象、与 Baseline 的关系、入库时机和迁移责任的决定均已明确，没有需要继续追问的领域前沿。实现中的接口与字段选择按这些决定展开，不把一般实现细节或具体资产归类再升级为用户决策。

已明确术语写入 CONTEXT.md，已确认的职责取舍记入 ADR 0006；本轮仅形成设计文档。
