# 大型研究产物与材料获取

本规格记录用户于 2026-09-15 确认的工作方式。目标是让 Agent 在已有授权与资源内完成实际研究，并把有价值的完整产物保存为后续可消费的精确版本。数据量、文件格式和是否涉及代码不决定一项工作的研究身份。

## 工作组织

只有 Bundle Session 通过正式候选接纳与调度流程启用 Target。下载、采集、清洗、标注、切分和整理研究材料都可成为 Target 的实际动作，也可与其后的研究放在同一 Target。是否拆分、保存多少中间状态以及何时评价，由 Agent 根据研究价值、真实依赖、复用与恢复成本、存储资源判断。湿实验、观察记录、文字论证与辅助材料沿同一研究过程处理。

| 对象 | 材料获取与整理中的含义 |
| --- | --- |
| Baseline / Variant | 来源特点、获取或处理方法及具体实施配方；本次精确版本留在运行输入绑定 |
| VariantRun | 实际获取、处理或其他实施，以及原始材料、整理后数据、日志与保留状态 |
| Evaluation / ProtocolVersion | 完整性、来源、适用性或其他检查的安排和判据 |
| EvaluationAttempt | 实际实施的检查及其 Markdown 等报告、日志；可无数值指标 |
| Dataset / DatasetVersion | 值得复用的数据集合的语义身份，以及绑定已接纳 RM 内容的精确版本 |

纯报告评价可以声明空的指标集合，执行后的 `metrics` 为 `{}`，检查依据、发现及局限由归属该 EvaluationAttempt 的报告承载。现有 MetricResult 保留空指标图和精确结果文档来源，不能据此声称测得任何数值。已声明的 required Metric 仍须满足。尚未评价、失败和阻塞保留实际状态，不由文件存在或进程退出推断成功评价。

## 内容保存与消费

数据产物惯例目录为 `outputs/data/`；实现、checkpoint、分析和日志使用既有 completion 目录。Target 选择值得保留的文件或目录，声明真实 `formal_runs` 及每个生产者的 `artifact_paths`。系统在普通交接流程内按产物规模选择保存方式，大型文件或目录流式进入 RM 受管内容存储；Agent 无需填写大/小模式，也无需为跨越旧交接包阈值机械切成小归档。只有单一实际生产者可以使用目录惯例推断归属，多个生产者须显式指定产物。

完成写入后保持所选路径稳定，直到取得 Owner 接纳。后续 Target 通过正式冻结输入引用精确 RM 版本，读取或物化实际数据；摘要、路径和哈希说明不替代内容。体积限制和资源故障应如实报告，不能把文件大小解释成额外人类授权。既有精确资产引用无需重新作为本次新产物打包。

交接层按精确 AssetVersion 及完整导出描述保存一份独立只读副本，位于服务数据根的 `run/target-input-assets/`。同一版本从直接引用、上游 Commit 或不同 Target 进入时，保持各自 manifest、来源、版本与路径，文件通过硬链接共用交接副本；目录保留完整结构及空目录。它与 RM 受管对象及 `linked_local` 原件分开保存，不共用原件 inode。首次交接由 RM 流式核验，跨进程版本锁及原子发布避免重复复制和半成品；普通恢复检查精确描述与文件结构，正式完成仍核验冻结输入的完整内容。既有冻结目录可继续使用；清理历史重复副本时必须先验证精确版本和完整文件，再原子替换为共享交接副本的硬链接，不能删除唯一来源。

每个文件不必登记一个 Dataset。Agent 选择有研究意义的集合、版本和来源关系；需要时用现有 Dataset 操作引用当前 Question，关联精确源版本与派生版本。Baseline 和 Dataset 可在同一服务数据根内跨 Quest 检索复用，引用本身不扩大当前阶段冻结输入、证据范围或执行授权。

受管副本与 `linked_local` 区分保存：后者仍依赖原稳定文件，不是备份。清理临时目录前确认保留的昂贵或不可替代数据已有可用副本，且不会删除已接纳版本依赖的唯一来源。

## 人机协作边界

已授权的获取、整理、检查和保存自主推进。只有具体缺少外部访问权限、受限材料、额外资源或需要人类亲自执行的行动时，使用 `human_request` 说明已完成工作、真实阻碍、准备好的材料位置和所需帮助。多 GB 产物本身不触发例行“请人导入”。技术故障按原工作恢复，已有精确资产和已接纳研究事实保持原版本。
