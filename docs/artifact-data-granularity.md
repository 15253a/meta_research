# 研究粒度与数据来源

本次补充基于当前 8768 提交 `dae5844b5cff077453790e74739fff4aede5ba76`，实现用户对 Agent 自主把握粒度和 Dataset 来源关系的要求。

## 用户要求

一次执行或评价需要保存什么产物、多少 checkpoint、保存到什么粒度，由 Agent 自行权衡研究价值、未来复用、重获成本与存储负担。总体 system prompt 用一句话表达这种粒度判断。数据是研究的重要基础，应特别注意处理、保存和来源关系；沿用已有 Dataset 模型，避免重复资产系统。

## 实际行为

- Agent 自主确定研究问题、工作安排、执行、评价和产物保存的粒度。共享 system prompt 覆盖所有阶段和 Target。
- `checkpoint_policy` 保留兼容字段和既有建议，`required`、`optional`、`forbidden` 都不再决定产物有无的接纳资格。实际可以保留多个、部分或零个 checkpoint。选择没有保存状态时传空列表，不生成占位状态。
- 保存的内容仍需和精确版本、hash、真实 Run、评价所用状态一致。执行与评价各自保存实际产物；没有评价时不生成评价记录。
- 沿用 Dataset 身份、DatasetVersion 对 RM 精确版本的绑定、数据与 Question／研究对象的用途引用。新增精确数据版本之间的派生关系，表达清洗、标注、切分、合并等处理，记录处理说明。多个来源分别建立关系，Agent 判断哪些处理值得单独登记。
- 数据身份和相关的精确研究对象可以跨 Quest 复用；写入的 Question 必须属于当前已认证 Root 的 Quest。可选研究引用表达关联出处，登记关系不复制数据，也不证明所记录的处理已经被独立复核。

例如：原始访谈记录 → 脱敏文本 → 编码表。三者可以是同一 Dataset 的不同版本，也可以按研究含义属于不同 Dataset；Agent 选择粒度，关系记录精确来源与处理方法。实验室原始读数、调查数据、算法训练数据同样适用。

## 数据保存边界

优先保护昂贵或不可替代的原始数据，保存来源、处理方法和可重建条件。临时中间文件是否保留由 Agent 判断；清理前确认不会删除唯一原始来源或仍被引用的精确版本。

RM 管实际文件和版本，RG 管 Dataset 的身份、用途和来源。已有 `linked_local` 资产接入可异步流式校验大型文件，登记不会复制或备份外部内容。当前 Root MCP 只有已接纳版本的 Dataset 登记，没有通用文件导入工具；不能把 `datasets.register_version` 当成文件上传。

Target 默认交接包仍有单资产 64 MiB、总计 256 MiB 的技术限额。大型数据可先保存在稳定持久路径，交接中记录路径与来源；已有已接纳 RM 版本时直接精确引用，需要新资产正式接入时通过现有资产入口或人类协助完成。Target 正常完成或停止不会自动删除其研究工作目录。保存数量由 Agent 判断，包容量限制仍需遵守。

## 验证范围

验证应覆盖真实 Owner 接纳零个和多个 checkpoint、精确产物归属与错误 hash 拒绝，Dataset 派生关系的多来源、精确读取、分页、稳定重放、错误归属与环拒绝，以及所有 Root 的实际提示和工具入口。部署使用现有 8768 的空研究 data，隔离测试数据；保留 8767 历史数据。
