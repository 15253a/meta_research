## 2. 按已确定的研究方式改进

RG 保持 Question、Baseline、Dataset、Literature、HumanRequest／人类输入五个研究入口，返回对象身份、含义、来源、关系及可直接读取的精确内容引用。对象详情在入口内展开；实际正文与文件共用 RM 读取。参考阅读、采用为依据、绑定实际执行输入分别表达，使用同一原件不重复复制或建立另一套资产身份。

入口查询和关系展开返回有界、可继续分页的摘要与稳定引用。根／子智能体均能在当前任务范围内自行查询并沿引用继续读取，不先把全库正文装入根上下文再复制分发。沿用现有分页和查询底座，按实际瓶颈改进。

Target 可以跨多个 Baseline，自主决定复用或新建 Baseline、Variant、VariantRun 及真实发生的评价对象。Bundle 的初始方案不能把 Target 最终方法与归类锁死。固定科研层级保持为：Baseline → Variant → VariantRun，以及 Variant → Evaluation（关联精确 ProtocolVersion）→ EvaluationAttempt → MetricResult。每个实际 Run 关联自己真正使用的实现和输入版本。没有开展评价就不制造 Attempt 或结果；失败、分析和负结果如实表达。

保留的科研产物必须有相应研究归属；只出现在 RM 文件清单或 TargetCommit 下不算完成。TargetRun 继续承担 AR 执行与恢复，TargetCommit 承担本阶段交接及出处。具有独立数据复用价值的产物可登记 Dataset，关联原实施与同一内容。归类错误可以直接调整关系并留下简短理由，精确内容引用保持可用，避免复制资产和建立另一套分类审批流程。

归类纠正必须从相应 Owner 的可维护关系完成，并同步处理有关读取逻辑。当前产物归属参与接纳回执与历史读取校验：只改 SQL 外键可能破坏旧来源读取，简单关闭完整性检查也不是实现。用最小改动实现当前归属可纠正，同时保持内容版本、实际执行事实和历史引用可解析；不把这个要求扩张成旧分类全量副本或新的审计系统。

退出按材料类型授予“正式证据资格”的旧限制。MetricResult 仍只表示实际评价结果；理论、观察、分析、负结果、人类专业意见也能被研究采用，由 Agent 说明依据、适用范围和不确定性。保留真实来源、版本、权限和归属核验。对 `research_notes`、`plan_evidence`、`reasoning_evidence`、`implementation_content` 先按实际职责拆清发现、正文读取、执行输入和阶段上下文，再替换或收拢；不要只换名字、保留同样的阶段拼接负担。

阶段职责落实到真实 skill 与工具：

- Idea 理解当前 Question 和研究交接，充分查读文献、结合已有积累，提出可能的研究方向、假设和方法思路，供 Plan 选择投入。查找、取得、精读和比较文献可以是其主要工作。
- Plan 明确本轮投入、研究承诺、所选依据、适用判据和现实条件；不预先决定 Target 全部实际方法及归类。
- Bundle 组织工作和真实依赖，Target 实施、局部修订并交接归类后的产物；第一版先完成同一批 Target，再汇总利用这些工作，不引入中途科研资产发布及提前消费。正常文件保存、日志观察、已有资产整理及恢复继续工作。
- Reasoning 综合实际工作与历史认识，形成 Question 的研究历史并决定后继；综合发现无须包装成 Target。Reasoning 内 DeepFetch 仅服务于拟创建新问题的路径，保持标准 summary.md，由原 Reasoning Session 阅读、调整并继续判断；普通综合与补充阅读不走该专用路径。后继入口保持 Idea、Plan 或 Reasoning。

各根 Session 做 review 时必须委派独立子智能体，主 Agent 根据问题修改草稿。Reasoning 合理委派阅读、召回、分析；资产池较大、检索、索引整理、归类或入库工作量较大时，也应合理委派独立子智能体。工具及会话权限须实际支持所委派的任务，不能只在 skill 写“可以委派”。采用既有子会话机制，不新增 review 记录、批准流程、固定子智能体数量或另一套调度系统。

检查实际加载的 SKILL.md、references、共享指导、动态提示与必要适配代码，统一相反指令。当前 Idea／Plan／Reasoning 存在同根 Session 第二个 turn 的 advisory review 约定，Bundle 也有对子智能体最终工作区写入的限制，不能只在新稿里追加一句新规则。主 Agent 的第二个 turn 可以继续承担改稿，但不能被当作独立 review。整理和入库委派按明确任务范围处理读写与并发，仍由对应 Owner 保持权威接纳；退出不再需要的 review 专用填报与接纳要求，不换成另一套 reviewer 资格证明。

## 4. 用行为验证完成度

针对受影响路径先确定当前基线，再运行有意义的行为检查。至少覆盖：

1. 不同 RG 入口发现同一原件，能沿同一精确内容引用读取；Question、方法、数据、文献、人类输入各自可以展开必要信息。
2. Target 自主创建或复用跨 Baseline 的对象；每个实际 Run 保留真实实现、输入和产物归属。无评价分析工作可以完成并被后续采用。
3. Target 已保存的科研产物都能从对应层级找到；Dataset 登记共用内容并保留来源，重复提交不会重复创建实际工作或复制原件。
4. 后续纠正归属后，当前入口位置正确，共用内容和旧交接引用仍可读取；技术性保存／接纳失败能继续交接，不重跑已经完成的科研工作。
5. 直接进入 Reasoning 的一轮可以阅读历史、理论分析和人类意见形成综合；无需伪造新 Plan、Target 或 MetricResult。拟建题 DeepFetch 完成后由原 Reasoning Session 继续判断，恢复不重复建题。
6. Idea 的文献研究与方向探索可实际进行；各根 Session 的独立 review 和按规模委派能力可实际使用，受派子智能体能读取必要材料并完成获授任务。在较大隔离资产池验证分页和继续读取，根 Agent 不需要事先取得全量正文；仍在实际加载的旧相反指令要消除。
7. 用至少一个隔离完整研究场景走通“查找／读取 → 选择投入 → 实际工作 → 归类交接 → 综合 → 后续再次找到并使用”。现有历史测试失败与本次新增失败分别报告。
