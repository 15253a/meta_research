# 科研资产按研究含义组织，并共用精确内容引用

2026-09-22，用户明确本次优化以理顺 RG／RM 资产归属和读写为中心。RG、RM、AE、AR、HC 的深模块架构保留；RG 以 Question、Baseline、Dataset、Literature、HumanRequest／人类输入为五个研究入口。此记录确认设计约束，不表示实现或部署已经完成。

Baseline → Variant → VariantRun 表达方法、具体方案与真实实施；Variant → Evaluation → EvaluationAttempt → MetricResult 表达关联精确 ProtocolVersion 的评价及其实际结果。Target 的真实工作有对应实施记录，所保留的科研产物按含义进入上述层级；未开展评价不制造评估实施或结果。Target／TargetCommit 可保留执行与交接出处，仅挂在其下不算完成科研资产归类。具有独立数据复用价值的产物还可登记为 Dataset，关联原实施和同一内容。

用户在本轮追问中进一步明确：Baseline 层级服务于 Target 检索、复用和积累资产，不限制一个 Target 只能使用一个 Baseline。由 Target Agent 根据实际工作决定复用或新建哪个层级的对象：沿用方法 A 而采用新配置，可以在 Baseline A 下新增 Variant；深入比较 A、B 若形成独立研究方法，可以建立 Baseline C，并关联实际采用的工作。比较本身不强制产生新 Baseline，纯总结和综合推理可以由 Reasoning 完成。TargetRun 承载这段研究活动及修订、恢复和入库过程，TargetCommit 侧重本轮本阶段的交接，二者均不替代科研资产归属。

Bundle 继续组织工作、依赖和交接，可以给出初始方法方案；它不提前锁定 Target 所有实际采用的方法及最终资产归类。Target Agent 在实际工作中决定复用和新建，系统负责把这些决定准确保存并提供后续读取。具体入库与阶段交接可以由 Target 完成，也可以由 Bundle 根据 Target 的交接完成，不因此改变科研归属。复杂、耗时的 Target 保留可单独管理的 Session，以便持续执行和恢复。

第一版先完成同一批 Target，再围绕完成后的科研产物做好归类、汇总交接和后续使用。用户明确暂不实施长 Target 中途把部分工作提前入库、对外提供研究入口读取，以及基于这些中间产物提前开展依赖工作的优化。该范围限制不影响正常执行保存和恢复，也不引入新的整批原子提交机制；优先完成一致的资产归属和读写路径。

RM 保存实际内容与精确版本，RG 保存研究含义、归属、用途及关系。从不同入口发现同一原件时继续使用同一内容引用。研究发现回到五个入口，具体对象的材料由对象详情和关系展开，正文共用 RM 读取；当前交接、执行恢复和 Owner 协作留在各自职责内。由此避免 Agent 为读一份材料拼接多套阶段路径，也避免把内部包装扩大为新的资产层级。

后续 Agent 可以纠正归类：直接调整或移动当前归属，留下简短理由即可。归类纠正不要求保留一套旧归属副本，不复制资产正文，也不因一次移动新造实施或评价；同一内容的精确引用继续有效。相应维护能力支持 Agent 整理研究积累，不增加独立审批或审计流程。

Literature 保留有研究意义的阅读差异及其研究背景，可以提供更新的综合摘要，但不机械地为每次阅读生成整套记录或复制原文。已有内容与判断能复用就复用；需要补充或修正时仅保存必要的判断和出处，摘要不抹去影响研究理解的分歧。

研究依据不设按材料类型划分的资格目录。MetricResult 继续表达实际评价结果；理论论证、观察、分析、负结果与人类专业意见也可参与判断，由 Agent 解释依据、适用范围和不确定性，系统保存真实来源、版本和归属。EvidenceRef 等包装仅按实际引用用途保留或精简，不要求为引用材料补造评价。此决定取代 ADR 0004 中把 Plan 的依据选择限定为“正式 Evidence”的表述；该 ADR 的后继入口和阶段责任决定保持有效。

Idea 围绕当前研究问题，通过文献与已有研究积累探索可能的研究方向、假设和方法思路。文献检索、查读和比较可以构成 Idea 的主要工作；它向 Plan 交接方向、来源、理由及待澄清的问题，不把职责收窄为解释已有结果。

Reasoning 可以通过阅读和综合形成分析发现，并关联对应 Question 的研究历史，不必变成 Target。用户进一步限定：Reasoning 内的 DeepFetch 只服务于创建新问题的路径，不作为普通综合或一般补充阅读的通用步骤。拟建新题时按需调用 DeepFetch、取得标准 summary.md，由原 Reasoning Session 阅读并调整，再判断是否建题。

Reasoning 应合理使用子智能体承担聚焦的阅读、历史召回、对照分析等工作。各根 Session 如进行 review，必须使用独立子智能体指出问题，再由主智能体改稿；当检索、索引整理、归类或入库工作量较大，尤其研究资产持续增长时，也应合理委派独立子智能体分担。根 Agent 组织分工并综合判断，工具支持在任务和权限范围内完成相应工作；不要求根 Agent 先读完整个资产池再委派，也不把所有子智能体限定为只读检索。具体做法写入 skill，不新增 review 记录、审计、批准流程或科研资产层级。

选择这些职责是为了让研究积累脱离临时阶段包装而可长期查找、理解与使用，同时保持真实实施和实际评价的区别。具体科研归类交由 Agent 判断，skill 提供使用指引，系统支持准确保存、关联、查询、必要纠正与运行接续；不再为每一种比较、总结或材料组合制定新的分类规则。
