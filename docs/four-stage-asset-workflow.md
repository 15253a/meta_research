# 四阶段职责、工具、资产与交接：第一版讨论稿

2026-09-24 补充：本文原有“五入口”设计已由 [ADR 0006](adr/0006-environment-as-reusable-research-index.md) 扩展为含 Environment 的六入口。Question 侧重进展总览，Baseline／Target 和 HumanRequest 侧重过程方法积累，Literature、Dataset、Environment 侧重产物与资源复用。Environment 还包括已有设备、设施及现实物理资源，可按来源直接登记；Target 新产物与 Dataset 同环节整理，其他机器的适配或修复属于新 Target。Baseline 层级及五个 Owner 保持不变，本文历史内容不表示 Environment 已实现。

状态：供用户逐项审阅的目标设计，不表示现有工具均已具备，也不把本稿新增的接口建议视为已确认决定。遵守 Q1–Q4：Target 自主在 Baseline 层级内复用和创建；归类纠正轻量；内容少副本；同批 Target 先完成，不增加中途科研资产发布和提前消费。

## 1. 四阶段分别对什么负责

| 阶段 | 必须作出的研究决定 | 交给下一阶段的核心 |
| --- | --- | --- |
| Idea | 围绕当前问题，基于文献和已有研究积累探索可能的研究方向、假设和方法思路；文献检索、查读和比较可以是主要工作 | 有来源和理由的研究方向、方法思路及待澄清的问题，允许一个或多个，数量由研究需要决定 |
| Plan | 本轮具体投入什么、承担什么研究责任、采用哪些已有认识、如何判断结果和重新考虑投入 | 本轮计划、承诺、适用判据、资源条件、已选依据与未决事项 |
| Bundle，含 Target | Bundle 把计划组织成可实施的工作；Target 决定实际方法、开展工作并整理真实产物；Bundle 根据完成情况继续组织或收口 | 实际做了什么、没有做什么及原因、归类后的产物、已有依据和仍未解决的事项 |
| Reasoning | 综合本轮与已有研究，形成对问题的当前认识，并决定后继问题、研究方向与入口 | 研究综合、认识变化或未变、依据和局限、下一步决定及原因 |

四阶段均可阅读五个 RG 入口、读取 RM 正文、获得相关人类输入，也可按需检索和委派。它们按研究决定分工，不各自拥有一份隔离的文献、数据或结果库；也不要求各阶段平均使用五个入口，Idea 可以把大量工作投入文献检索与精读。

## 2. 研究语义和系统职责归到哪里

| 模块 | 持有的事实及职责 | 与四阶段的关系 |
| --- | --- | --- |
| RG | Quest／Question、方法层级、Dataset、Literature 的研究身份、归属、用途和关系；研究构想、计划和综合的语义接纳 | IdeaSet、FormalPlan、ScientificOutcome 可从 Question 的研究历史展开；TargetGraph／Target 描述工作及依赖，TargetCommit 连接交接出处和已归类科研工作；这些不新增并列研究入口 |
| RM | 已保留正文、代码、配置、数据、文献、模型、分析和报告的精确内容版本及读取、保存、导出 | 所有阶段共用内容引用；从不同入口找到同一原件，继续读同一版本 |
| AE | Cycle、阶段请求、阶段完成、跳过与后继推进 | 保存 StageCommit 及继续到哪里的控制事实；不代替 Agent 作科研判断 |
| AR | 根／子 Session、Attempt、TargetRun、实际执行、观察、恢复与运行交接 | 为四阶段运行 Agent；为复杂 Target 保留独立 Session；接收 Bundle 的执行汇总并供 AE 推进 |
| HC 与请求原 Owner | HC 接收并交付人类回复、指导和材料；请求的签发、等待条件及解决判断仍由对应 Owner 维护 | RG 人类输入入口提供研究发现和关系，不能把建议自动变成授权，也不接管原 Owner 的运行职责 |

关键对象的归属不随所在阶段改名：IdeaSet、FormalPlan、ScientificOutcome 的研究含义在 RG，正文在 RM；阶段完成在 AE。Obligation 是计划内的研究承诺，不增加独立 Owner。TargetRun 在 AR，VariantRun 在 RG。TargetCommit 在 RG 表达已接纳的 Target 交接，BundleReport 在 AR 表达执行汇总，二者都不替代 Baseline 的科研归属。

Idea／Plan 的已保留正文和采用依据可经 Question 历史找到，但它们的构想和计划不被记成已实施的研究结果。Reasoning 的分析发现归到相关问题的认识历史，不必为了存档制造一个 Target。

## 3. 应提供给 Agent 的工具能力

下列名称是说明能力的接口示意，不声称当前 MCP 已有这些名称，也不要求机械地实现相同数量的工具。工具以研究对象或实际操作为中心，凭当前会话自动取得研究范围和运行绑定；Agent 不手工拼接 Owner 回执与阶段技术字段。

### 所有阶段共用

| 能力 | Agent 表达什么 | 系统返回或完成什么 |
| --- | --- | --- |
| 五入口查询与对象详情 | 在 Question、Baseline、Dataset、Literature、人类输入中查找相关对象；阅读一个已知对象 | 精简摘要、稳定对象引用、相关状态、来源、可展开关系及可读取内容引用 |
| 关系展开 | 从 Variant 看 Run，从 Run 看输入、产物、评价，从数据看使用和派生，从 Question 看结构及研究历史 | 按权威事实展开双向关系，不让 Agent 另外维护一套反向边 |
| RM 内容读取 | 提供精确内容引用，必要时选择目录成员、段落或范围 | 原文、目录清单或可读取的本地材料；大文件可导出到工作区，同一来源保持一致 |
| RM 内容保存 | 指定值得保留的文件、目录或正文，已有版本直接引用 | 精确内容版本；阶段提交可内部完成保存，避免让 Agent 为每份交接重复跑保存协议 |
| 研究整理 | 给对应对象补充说明、用途或引用；明确指出错误归属及改动理由 | 在相关语义模块内调整关系，保留精确内容引用，不提供任意改图或改运行状态的通用入口 |
| 人机协作 | 说明实际困惑、已尝试工作、需要的判断／材料／现实帮助 | 经 HC 与原 Owner 提出具体请求并读取适用回复；主动人类输入也能找到 |
| 检索、委派和工作区操作 | 围绕具体问题查材料，委派聚焦阅读、对照分析，以及工作量较大的索引整理、归类和入库；编写草稿 | 可恢复的会话与适当权限范围内的研究操作能力；根 Agent 组织分工并负责综合判断，不把所有工作集中在一个上下文 |

阅读材料、采用为论据、绑定为执行输入是三个不同动作。读过不自动算采用；采用为论据不要求先变成执行输入；真正执行时保存实际使用的版本。取消材料类型资格，不取消来源真实性和精确版本。

### 阶段专用能力

| 阶段 | 还需要什么工具 | 不要求 Agent 手工做什么 |
| --- | --- | --- |
| Idea | 读取本轮问题及前驱交接；充分检索、取得并阅读相关文献，结合已有资产探索研究方向；提交构想与来源，例如 `idea.submit` | 不手工写 StageCommit，不提前登记虚构 Run |
| Plan | 读取 Idea 与当前条件；提交本轮计划和研究承诺，例如 `plan.submit` | 不把方法候选锁成 Target 最终全部归类，不给普通材料申请证据资格 |
| Bundle | 提出／调整 Target 与真实依赖、启动并观察本批工作、接收完成交接、提交执行汇总 | 不逐次重建已接纳上游的整套历史证明，不复制 Target 全部正文 |
| Target | 读取自己的任务和实际输入、执行代码或其他工作、观察和局部修订；按实际工作声明所用或新建方法对象、Run、评价与产物归属；提交完成交接，例如 `target.complete` | 不按一个工具调用制造一个 Run，不强制补评价；不只上传文件而漏掉科研归属 |
| Reasoning | 读取本轮与历史，合理委派聚焦阅读、召回和分析；仅在拟建新问题的路径按需请求 DeepFetch，并在原 Session 接着读 summary.md；提交综合、问题关系／新题判断及后继决定，例如 `reasoning.submit` | 不把一般综合或补充阅读都导向 DeepFetch，不让 DeepFetch 代替自己决定新题，不为综合分析另造 Target，不直接进入下一轮 Bundle |

提交入口应把模块协作藏在内部：Agent 给出研究含义、所选内容和交接；RM 保存内容，RG 记录相关语义，AR／AE 完成各自运行与阶段事实。具体动作仍由对应 Owner 承担，不新增一个第六 Owner 或一套通用资格审批。

复杂工作允许 Target 自己决定方法和归类；Bundle 可以协助整理完成交接。推荐正常路径由最了解实际工作的 Target 提供产物归属，Bundle 检查是否能支撑本轮交接并整理未决事项。这是协作建议，不新增必经 review 或接纳关卡。

## 4. 落盘应分清三种位置

### 工作区

AR 为当前会话／执行安排工作区。草稿、源代码编辑、运行中的日志、临时文件和未决定保留的输出先在这里产生。文件已经出现在工作区，不等于已经成为可长期复用的科研资产。

示例文件名如 `idea.md`、`plan.md`、`outputs/model.bin`、`outputs/analysis.md`、`reasoning.md` 只帮助理解，不把文件名或目录惯例当作科研含义的唯一判断依据。

### RM 受管内容存储

被选定保留的正文及产物进入 RM，取得精确版本。阶段自己的最终正文也按需保存一份：Idea 的构想正文、Plan 的计划正文、Target 的代码／配置／输入关联和输出、Reasoning 的综合正文等。

同一原件不因被 Plan 引用、Target 使用、Dataset 登记和 Reasoning 讨论而各存一份正文。实际内容确实改变时才涉及新内容版本；归类移动只改关系。执行输入的必要本地交付由系统处理，不成为新的研究身份。

### 各 Owner 的持久记录

RG 保存研究身份、可查询说明、归属和精确内容引用；AE 保存阶段接续；AR 保存 Session、运行状态和 BundleReport；HC／原 Owner 保存对应协作事实。这些逻辑职责可以共用现有数据库，不对应五套目录或五个服务。

Agent 只需知道工具返回的工作区路径、对象引用和内容引用。数据库文件、内容寻址及物理文件布局由系统维护，不要求 Agent 直接写表或拼出受管对象路径。

可以沿用当前已经存在的物理位置。下表中的 `<研究目录>` 是本次研究自己的 data root；不是开发 worktree，也不借此访问旧研究或相邻目录。

| 物理位置 | 用途 |
| --- | --- |
| `<研究目录>/meta-research.sqlite3` | RG／RM／AE／AR／HC 各自负责的结构记录、索引、运行及接续事实；物理共库不改变职责 |
| `<研究目录>/objects/sha256/` | RM 受管内容，按内容寻址；Agent 通过精确引用读取，不依赖内部文件名 |
| `<研究目录>/idea-skill-provider/research-workspace/` | Idea 可写工作区，具体会话位置由工具提供 |
| `<研究目录>/plan-skill-provider/research-workspace/` | Plan 可写工作区 |
| `<研究目录>/bundle-skill-provider/research-workspace/` | Bundle 可写工作区 |
| `<研究目录>/reasoning-skill-provider/research-workspace/` | Reasoning 可写工作区 |
| `<研究目录>/run/target-workspaces/` | 各 Target 的实际执行工作区 |
| `<研究目录>/provider-homes/codex/sessions/` | Provider 原生会话及恢复所需记录，不作为科研资产入口 |

明确登记的外置资产仍按其精确来源读取；登记不等于备份，内容变化不能静默当作旧版本。无需为了统一入口把已有有效内容再复制到一个“Baseline 文件夹”或“Dataset 文件夹”。

### 各阶段的落盘与交接

| 阶段 | 长期保留内容 | 研究或运行归属 | 给下一阶段的交接 |
| --- | --- | --- | --- |
| Idea | 被保留的构想、理由、重要来源与未知的正文 | RG IdeaSet 关联 Question／Cycle；正文在 RM；阶段完成在 AE | 当前问题和已有认识、候选构想及依据、重要分歧与未知、精确读取入口 |
| Plan | 本轮计划、研究承诺、判据、资源条件、所选依据与未决事项 | RG FormalPlan，Obligation 属于计划；正文在 RM；阶段完成在 AE | 做什么与为什么做、可用材料、范围和现实条件、何时重新判断；不机械列死每个 Target |
| Bundle／Target | 实际保留的实现版本、配置、数据、模型、观察、分析、评价报告；必要工作说明 | RG 方法层级及 Dataset 关系；内容在 RM；TargetRun 在 AR；TargetCommit 保留交接出处 | 每项工作真实状态、已登记 Run／产物／评价引用、失败与未做原因、剩余问题、对本轮承诺的覆盖情况 |
| Bundle 汇总 | 简洁的工作汇总和交接引用；如有独立保留价值的研究说明，其正文可保存 RM | BundleReport 保持 AR 的执行交接职责，AE 据此推进；RM 正文共用读取是目标设计建议，非现行已具备事实 | 给 Reasoning 一份可读的本轮实际工作概览及精确阅读入口，不复制所有 Target 报告 |
| Reasoning | 综合认识、采用来源、适用边界、认识变化、后继选择及理由 | RG ScientificOutcome 关联 Question 研究历史；正文在 RM；AE 执行后继决定 | 下一阶段需要的认识、历史依据、未决事项、人类条件及继续理由 |

阶段交接不等于再建一份研究资产副本：值得保留的正文存一次，交接携带必要摘要和原内容引用。只服务当前接续的调度状态、游标和运行信息仍在任务上下文及 AR／AE 中，不加入新的科研入口。

## 5. 用一个完整例子走一遍

以下项目、结果、百分比和人类意见全部是假设示例，用于检查职责与归属，不是实际实验或已有科研结论。

### 已有研究背景

Quest 是“提高设备之间的故障识别可靠性”。Question 树里当前问题 Q1 是“从设备 A 换到设备 B 后性能下降，预处理或方法调整能否改善”。已有：

- Dataset D1/v1：两台设备的带标签信号，以及设备、采集时间等元数据。
- Baseline A：一种已有分类方法，有原配置 V0、历史实施和原文可读的实现。
- Baseline B：另一种已有分类方法及相应材料。
- Literature L1：一篇讨论输入标准化的文献，已经取得精确原文版本。
- 人类主动指导 G1：“设备 B 的资料主要来自冬季，注意是否有采集条件变化。”它是有来源的人类说明，不自动等同于因果证据。

### Idea：基于文献与已有研究探索研究方向

Idea 从 Question 入口读问题结构和相关历史，结合 A/B 的既有工作、D1 与 G1 明确当前背景。它可以把本阶段主要精力用于检索相关文献、精读方法和实验条件、比较已有思路与空缺；L1 是起点，不是预先限定的唯一文献。文献较多时，合理派子智能体按方向检索和阅读，根 Agent 核读关键原文并综合形成方向。

经文献与已有工作比较，它提出若干研究方向：研究输入标准化是否有助于跨设备迁移；探索另一种分类方法；研究设备与采集时段混杂如何影响当前判断。每项方向说明来源、思路、研究意义与尚待澄清之处，不要求都表现为对现有结果的一项解释，也无需为提出方向创建 Run。值得保存的新文献及阅读理解进入轻量 Literature 组织，原文由 RM 保存。

输出一份 `idea.md`。RM 保存正文，RG 的 IdeaSet 关联 Q1 和本轮 Cycle。交给 Plan 的是构想、理由、重要来源引用和未知，不是整个文献库，也不是已选定的执行清单。

### Plan：决定本轮投入和需要得到的认识

Plan 选定本轮责任：在可比较的条件下查看标准化和另一方法的表现，并审查设备／时间分布。已有的人类资源条件允许本轮使用一张 GPU；具体投入依实际授权安排，不把示例资源写成系统统一配额。

它明确：采用 D1/v1；比较使用同一切分和相同指标定义，所选精确评价协议版本为 ProtocolVersion P1；记录实际实现与配置；即使未改善也完成诚实比较；分布审查只要求说明真实观察及其局限，不要求人为产生指标或证明因果。

这些是本轮研究承诺和可比较条件。Plan 可以给出方法建议，但允许 Target 在承诺范围内调整实际配置和工作组织。若改变判据导致结果不可直接比较，必须如实说明，不能混用数值冒充相同条件；超出本轮已承诺核心科学语义的变化，不能算完成原比较，应交接变化原因和未完成责任，由 Reasoning 决定后继处理。这沿用既有阶段职责，不增加额外审批。

输出 `plan.md`。正文进入 RM，FormalPlan 及其研究承诺归 RG，实际采用的依据指向已有原件。交给 Bundle 的是本轮要回答什么、投入范围、判据、材料和现实条件；Plan 不接管 Session 和任务调度。

### Bundle：组织这一批工作

Bundle 将本轮工作安排为同一批三个 Target：

| Target | 工作 | 主要材料 |
| --- | --- | --- |
| T1 | 按 P1 比较 A 的原配置与加入标准化的新配置 | A、D1/v1、L1、P1 |
| T2 | 按 P1 实施并评价 B，供本轮比较 | B、D1/v1、P1 |
| T3 | 审查设备和采集时间的分布，保留有用的分组材料及分析 | D1/v1、G1 |

本例把它们拆开是为了任务管理方便。Agent 也可以在一个 Target 中比较 A/B，不因跨 Baseline 而强制拆分。

TargetGraph／Target 的研究工作和真实依赖由 RG 记录，AR 为 Target 管理独立 Session、TargetRun 及执行。各 Target 在工作区实际操作；Bundle 观察状态、处理需要协调的事项。第一版先完成这一批，不消费某个未完成 Target 的中间科研产物。

### Target：实际工作并给产物确定位置

T1 采用 A，保留原配置 V0，并为标准化方案建立 V1；实际各做一次实施，分别得到 R_A0、R_A1。它对两次实施按 P1 开展评价。T2 在 B 的相应 Variant 下实施并评价。T3 采用或建立“设备／时间分布审查”方法 C，产生 R_C1；没有安排独立评价，所以不创建 EvaluationAttempt 或 MetricResult。

以 T1 的新配置为例，归属为：

```text
Baseline A
└─ Variant V1：加入标准化的方案
   ├─ VariantRun R_A1
   │  ├─ 实际实现版本、配置、D1/v1 输入
   │  └─ 模型、实施日志等选定产物 → RM 精确版本
   └─ Evaluation E_A1：V1 + P1
      └─ EvaluationAttempt EA_A1：评价 R_A1
         ├─ 预测、评价日志和报告 → RM 精确版本
         └─ MetricResult：本次实际测得的指标

Baseline C：设备／时间分布审查方法
└─ Variant VC1
   └─ VariantRun R_C1
      ├─ 实际脚本、D1/v1 输入
      ├─ 分组标注表 → RM 版本 U
      └─ 分析报告 → RM 版本 W

Dataset D2/v1：可复用的设备／时间分组标注
├─ 内容 → 同一个 RM 版本 U
├─ 派生来源 → D1/v1
└─ 产生工作 → R_C1
```

### Baseline C 和 Variant VC1 具体存什么

C／VC1 是为了讲例子使用的代号。系统内它们是具有稳定引用的 RG 研究对象：方法的研究表述和方案参数构成对象内容，SQL 记录及 JSON 字段是其持久化方式。Agent 调用研究工具登记和读取对象，不直接写 SQL。

当前实现中，Baseline 的身份记录在 `rg_experiment_baselines`，显式方法身份／版本在 `rg_baseline_method_versions`，Variant 在 `rg_experiment_variants`。它们包含系统维护的哈希、出处和接纳时间；这些内部字段无需变成 Agent 填报的科研表单。

| 层级 | 可供 Agent 理解和使用的主要内容 | 本例 |
| --- | --- | --- |
| Baseline C | 稳定引用、方法名／版本，以及方法目的、输入含义、基本过程、输出含义和适用边界等方法表述 | “设备／时间分布审查”：用样本元数据检查设备与时间分组的覆盖和重叠，不据描述性统计断言因果 |
| Variant VC1 | 稳定引用、所属 Baseline，以及具体方案 `recipe` | 按设备×月份分组；时间缺失单列；统计样本数、设备内占比和覆盖；输出标注、交叉表与分布图 |
| VariantRun R_C1 | 所属 Variant、实际输入与实现版本、真实执行状态、保留产物及观察 | 本次实际使用 D1/v1 和某一脚本版本，得到 U、W 等产物，报告本次发现 |

Baseline C 的工具输入可以表达为：

```json
{
  "method_key": "device_time_distribution_audit",
  "method_version": "1",
  "method_contract": {
    "purpose": "检查设备类别与采集时段是否存在分布失衡或重叠不足",
    "input_semantics": "样本元数据，包含设备身份和采集时间",
    "procedure": "交叉分组，统计各组样本量，检查覆盖与重叠",
    "output_semantics": "样本分组标注、组级汇总与描述性分析；不据此断言因果"
  }
}
```

登记后系统返回 `baseline_ref`。VC1 关联它，具体 `recipe` 例如：

```json
{
  "group_by": ["device_id", "calendar_month"],
  "timezone": "Asia/Shanghai",
  "missing_time_policy": "单独列为未知组",
  "summaries": ["样本数", "设备内占比", "月份覆盖"],
  "outputs": ["样本分组标注", "交叉表", "分布图"]
}
```

上面的 `method_key`、`method_version`、`method_contract` 和 `recipe` 对应现有方法定义能力；内部说明字段只是本例写法，不是新增固定必填 schema。换成按季度分组可能形成同一方法的另一个 Variant，是否确实构成不同方案由 Agent 判断；对同一方案换一份数据实际执行，对应新的 Run。

具体的 D1/v1、实际脚本内容版本、执行结果和“本次发现某时段样本偏多”放到 R_C1 及其产物，不塞进通用方法定义。Variant 可以表达选样或处理规则，Run 记录本次真正采用的精确输入。

短方法说明和方案参数可以直接作为 RG 的结构字段／JSON 保存。长篇方法文档、代码和实际数据属于 RM 内容；需要时由对象关联。当前 Baseline／Variant 定义没有专门的 RM 正文引用列，增加长文内容关联属于目标接口建议，不把它写成现有已具备字段，也不为每句方法说明单独生成一个文件或资产副本。

### 同批 Target 的实际结果与交接

D2 是 Agent 认为有独立复用价值才登记的数据，不要求把 T3 每个临时表都登记成 Dataset。D2 在本例供本批完成后的综合及后续研究使用，不在本批中途提供给 T1/T2。

假设本轮单次比较得到：原配置 A 为 78%，标准化 A 为 82%，B 为 81%；T3 发现设备与采集时段分布明显重叠不足。这些数值只是示例。每个实际 Run 关联自己真正使用的实现和输入；不能拿 T1 最后修改的源代码当作两个 Run 的共同历史实现。

Target 完成交接包括：实际做了什么、调整了什么、真实状态、所用／新建对象、保留文件及对应归属、评价及其真实结果、局限和未做事项。提交入口完成 RM 保存和 RG 归类；同一内容可被多处引用。TargetCommit 记录本次交接与执行出处，不成为这些产物唯一可被找到的位置。

### Bundle：交给 Reasoning 的是可读的事实概览

本批完成后，Bundle 说明三个 Target 的实际情况、Plan 的哪些承诺完成或未完成、尚存哪些条件和问题，并提供相应对象与原文引用。它可做组织所需的局部判断、建议补充工作；整轮对 Question 的认识及后继方向由 Reasoning 综合决定。

BundleReport 可概括为：“两项方法比较已完成；分布审查发现设备／采集时间混杂的线索；数值和原报告见相应 Run／Attempt；本轮尚未隔离两种因素。没有未完成的本批 Target。”报告不把 T3 的观察变成一项不存在的评价，也不把一次提升宣称为已解决泛化问题。

### Reasoning：解释这些工作改变了什么认识

Reasoning 先读 Bundle 的概览，再从 RG 展开必要 Run、Attempt、Dataset 和来源，用 RM 读关键原文；同时阅读 L1 和人类输入 G1。它不需要把全部训练日志装进上下文。

合理的本轮综合是：“在本轮切分和单次实施下，标准化 A 的结果比原配置高 4 个百分点，B 也有改善；这支持继续研究这些方法。设备与采集时间存在混杂线索，尚不能把差异单独归因于设备，也不能据一次结果声称方法普遍有效。”MetricResult、T3 的分析和人类说明分别按自身实际含义被采用。

Reasoning 可以把 A/B 的实际结果对照、T3 分析与人类输入的解释、相关问题历史召回分别交给聚焦子智能体，自己读取关键原文并综合认识，而不是先把所有资产读完再委派。这些分析与综合可直接进入 Q1 的研究历史，不另造 Target。

它查 Question 全貌，考虑是否已有“设备效应与采集时段影响如何区分”的问题。只有当它进入拟建新问题的路径时，才按需要调用 DeepFetch；取得标准 `summary.md` 后在原 Reasoning Session 继续阅读和调整，再判断是否建题。普通复盘、沿用或关联已有问题、补充阅读，不因需要外部材料就自动触发 DeepFetch。

假设它决定下一轮进入 Idea，为隔离混杂因素提出新的研究构想。它交接当前认识、关键来源、仍未解决的问题、后继理由和现实条件；RG 保存 ScientificOutcome、问题历史及必要关系，RM 保存 `reasoning.md`，AE 按该决定接续下一 Cycle。后继仍为 Idea／Plan／Reasoning 之一，不直接进入 Bundle。

## 6. 后续 Agent 应当怎样找到这些积累

后续 Plan 查 Baseline A，可以找到 V1、R_A1、实际实现、D1/v1 输入与 E_A1／EA_A1 的评价。查 Dataset D2，可以读同一份分组标注并反查 R_C1。查 Question Q1，可以看到问题结构、相关研究和本轮认识变化。查 Literature L1 或人类输入 G1，可以找到原文、判断背景和采用位置。

这些阅读不要求先找到旧 Target Session 并解析其最终发言。需要追查执行过程时仍可沿出处进入 TargetRun；需要看原阶段的取舍时仍可展开 Idea／Plan／Reasoning 的正文。科研资产与运行交接各有用途，而正文保持单一精确引用。

所有根 Session 如果做 review，都委派独立子智能体指出问题，再由根 Agent 改稿。review 不产生新的科研资产、审计记录或批准步骤。

子智能体也应分担规模较大的索引整理、归类和入库。例如同批 Target 完成后产物很多，可以按生产者或明确资产范围分工，读取相关材料、确定归属并在授予的任务权限内完成登记，返回对象／内容引用、整理说明及未决项。已记录的产生和使用关系由系统直接展开，Agent 分工处理需要研究判断的整理，不重复手填反向索引。根 Agent 负责协调、处理分歧并形成交接，无须把全部内容再次读入自己的上下文或重新做一遍登记。

研究资产越多，检索和索引整理本身越可能成为主要工作量，应由 skill 明确指导按实际规模合理委派独立子智能体，不设固定数量、固定阈值或逐阶段强制委派。Reasoning 同样适用上述分工；涉及 review 时仍须使用独立子智能体。第一版涉及本批 Target 新产物的入库整理沿完成后的交接开展，不扩展为未完成 Target 的中间产物发布；已有研究资产可按需检索和整理。来源、版本、归属、查询及接续由系统实现。
