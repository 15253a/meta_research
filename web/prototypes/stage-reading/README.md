## 已选组合：对话流作为主阅读区

| 位置 | 组件与阅读方式 |
| --- | --- |
| 顶部 | 当前研究问题与阶段位置；Idea、Plan 已有材料，Bundle 当前活动，Reasoning 尚未进入 |

| 右侧研究助手 | 独立助手对话、软约束与授权记录、研究控制草案 |

问题树、研究资料、写作、历史、阶段详情与创建任务以演示面板或对话框承接。尚未满足条件的报告、后续问题与研究收口入口明确显示当前条件。资料获取与 Target 保留各自来源，不合并成 Stage 的时间线。

“需要你”场景提供一个明确范围的演示请求，可直接接受或拒绝。接受后显示等待系统核验；拒绝后显示等待智能体调整方案；两者都移除待办与重复提交入口，不向真实服务发送请求。默认等待场景表示已有授权回应，无需再次操作。

## 数据依据及后续实现接口

当前前端 `web/src/main.tsx` 的 `ResearchTracePanel` / `StageRawOutputFeed` 将原始 JSONL 直接放入 pre。现有数据中 `item.completed` 的 `agent_message.text` 可显示为正文；部分正文仍是 JSON，可将 `action` / `rationale` 按有据字段排版。工具记录按 item.id 合并开始、更新和完成事件。公开 root-observations 目前只包含 command_output / output_gap，不能单独还原完整主智能体活动流。

正式实现需分别保留 primary/review/autonomous-resume、dispatch-N 和 stream_ref 边界；stdout 字节序可以排序，文件 mtime 不是逐条事件发生时间。安全渲染正文和链接，正确处理 JSONL 半行、分页、累积输出、重复事件和缺失段。缺少说明时标记“尚未输出说明”，不生成伪造思考过程。

主任务、审查、Target 与资料获取保持独立来源；历史调度不显示为当前实时流。Provider 单次输出结束不等于 Stage 或 Cycle 完成，草稿也不等于最终实验结果。正式改造需按这些边界重新实现，不能直接将本原型部署为生产代码。
